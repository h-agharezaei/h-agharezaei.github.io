در مقاله‌ی قبلی، [trie و union-find](/fa/posts/algo-tries-union-find/)، پرسیدیم «این دو چیز به هم وصل‌اند؟» بدون اینکه مسیر را ببینیم. {{< term "graph" "گراف" >}} اجازه می‌دهد سؤال‌های سخت‌تر بپرسیم: چقدر فاصله دارند، از کدام مسیر، و آیا حلقه‌ای هست؟ پیمایش گراف به [queue یا stack](/fa/posts/algo-stacks-queues-deques/) نیاز دارد و هزینه‌اش دو متغیر دارد که به روش [Big-O](/fa/posts/algo-big-o-measured/) اندازه می‌گیریم.

> Go 1.26، مثال محلی، تست با `go test -race`. هنگام بررسی بار ماشین بالای ۴ بود، پس زمان منتشر نمی‌کنم؛ فقط شمارش و بایت.

## سه روش برای ذخیره‌ی گراف

یک گراف تصادفی بدون جهت با V=1000 رأس و E=5000 یال ساختم (seed برابر 42) و بایت‌ها را از ساختارهای واقعی روی ماشین ۶۴ بیتی حساب کردم:

```
adjacency list: 104000 bytes (exact elements), 132640 bytes (with append capacity)
adjacency matrix [][]bool: 1024000 bytes; as bits: 125000 bytes
edge list [][2]int: 80000 bytes; with int32: 40000 bytes
```

{{< term "adjacency-list" "لیست مجاورت" >}} (`[][]int`) حدود V + 2E عدد می‌گیرد و ۲۸ کیلوبایت اضافه ظرفیتی است که `append` جا گذاشته. ماتریس بدون توجه به E هزینه‌ی V به توان ۲ دارد؛ فقط برای گراف چگال یا وقتی «آیا یال u-v هست؟» را در O(1) می‌خواهید می‌ارزد. لیست یال کوچک‌ترین است ولی پیدا کردن همسایه‌های یک رأس یعنی پیمایش همه‌چیز. پیمایش همسایه می‌خواهد، پس لیست مجاورت را به کار می‌برم.

## BFS: اول نزدیک‌ترین

{{< term "bfs" "جست‌وجوی breadth-first" >}} یک queue نگه می‌دارد؛ اولین باری که به رأسی می‌رسد از کوتاه‌ترین مسیر (بر حسب تعداد یال) است، پس یک آرایه فاصله و یکی parent را می‌دهد:

```go
dist[src] = 0
queue := []int{src}
for len(queue) > 0 {
	u := queue[0]; queue = queue[1:]
	for _, v := range g.adj[u] {
		if dist[v] == -1 {
			dist[v], parent[v] = dist[u]+1, u
			queue = append(queue, v)
		}
	}
}
```

روی یک گراف ۸ رأسی (یال‌ها 0-1 0-2 1-3 1-4 2-5 4-6 5-6 6-7):

```
BFS dist from 0: [0 1 1 2 2 2 3 4]
path 0 -> 7: [0 1 4 6 7]
```

مسیر با دنبال کردن `parent` از ۷ به ۰ و معکوس کردن ساخته می‌شود. یک تست فاصله‌های BFS را روی ۳۰۰ گراف کوچک تصادفی (جهت‌دار و بدون جهت، با رأس‌های نارسا) با Floyd-Warshall و طول مسیرها را هم مقایسه می‌کند. سبز است.

## DFS: تا جای ممکن عمیق

{{< term "dfs" "جست‌وجوی depth-first" >}} یک شاخه را تا بن‌بست می‌رود و برمی‌گردد. بازگشتی پنج خط است؛ غیربازگشتی یک stack صریح دارد. ترتیب‌ها روی همان گراف:

```
DFS recursive : [0 1 3 4 6 5 2 7]
DFS iterative (pushed in order)  : [0 2 5 6 7 4 1 3]
DFS iterative (pushed reversed)  : [0 1 3 4 6 5 2 7]
```

اگر همسایه‌ها را به ترتیب push کنیم، stack آخری را اول برمی‌دارد و ترتیب فرق می‌کند. هر دو معتبرند؛ push معکوس همان ترتیب بازگشتی را می‌دهد که یک تست روی ۲۰۰ گراف تصادفی بررسی می‌کند. Go پشته‌ی goroutine را بزرگ می‌کند، پس یک تست بازگشت به عمق ۱٬۰۰۰٬۰۰۰ را روی گراف مسیری بی‌مشکل رد می‌کند. در Python حد پیش‌فرض ۱۰۰۰ فریم است؛ یک تابع بازگشتی با n=5000 را همان‌جا اجرا کردم و `RecursionError: maximum recursion depth exceeded` گرفتم. در Python از stack صریح استفاده کنید.

## پیمایش چه چیزهایی می‌دهد

**مؤلفه‌ها.** پیمایش از هر رأس دیده‌نشده، هر {{< term "connected-component" "مؤلفه‌ی همبند" >}} را برچسب می‌زند. روی ۹ رأس با یال‌های 0-1 1-2 3-4 5-6 6-7 7-5 خروجی `components: 4 [0 0 0 1 1 2 2 2 3]` است. یک تست برچسب‌ها را روی ۲۰۰ گراف تصادفی با union-find کوچک خودم مقایسه می‌کند و یکی‌اند.

**دور.** در گراف بدون جهت، رسیدن به رأس دیده‌شده‌ای که یال parent نیست یعنی دور. در گراف جهت‌دار کافی نیست، پس DFS سه رنگ دارد: سفید (تازه)، خاکستری (روی مسیر فعلی)، سیاه (تمام‌شده). دور دقیقاً وقتی هست که یالی به رأس خاکستری برسد.

```
directed  0->1->2, 0->2, 2->3 has cycle: false
directed  0->1->2->0 has cycle: true
undirected path 0-1-2 has cycle: false
undirected triangle has cycle: true
```

تست‌ها نسخه‌ی جهت‌دار را با topological sort از نوع Kahn و نسخه‌ی بدون جهت را با «تعداد یال > V منهای مؤلفه‌ها» می‌سنجند.

**دوبخشی.** با BFS رنگ‌آمیزی کنید و 0 و 1 را نوبتی بدهید؛ اگر یالی دو رأس هم‌رنگ را وصل کند، گراف {{< term "bipartite-graph" "دوبخشی" >}} نیست. مربع `true [0 1 0 1]` و مثلث `false` می‌دهد.

## شبکه هم گراف است

خانه‌ها رأس‌اند و چهار همسایه یال. flood fill جزیره‌های `#` را می‌شمارد:

```
aa..b..
a...b..
..c...d
..cc.dd
```

یعنی ۴ جزیره. مارپیچ هم BFS روی همین شبکه است؛ اولین رسیدن به `E` کوتاه‌ترین مسیر است (۱۵ قدم، `*` مسیر):

```
S.#*****
*##*###*
****#..*
###.#.#*
....#.#E
```

## اثبات O(V+E)

گراف‌های تصادفی با E=3V ساختم (seed برابر 7)، BFS را از هر رأس دیده‌نشده زدم و رأس‌های خارج‌شده از queue و بررسی یال‌ها را شمردم:

```
   V       E   vertices  edge checks  2E   V+2E
   1000    3000      1000         6000      6000      7000
  10000   30000     10000        60000     60000     70000
 100000  300000    100000       600000    600000    700000
1000000 3000000   1000000      6000000   6000000   7000000
```

هر رأس یک بار خارج می‌شود و هر یال از دو سر بررسی می‌شود: دقیقاً V + 2E، یعنی O(V+E). گراف ده برابر، کار ده برابر.

## چند نکته‌ی مهم

- رأس را هنگام enqueue علامت بزنید، نه هنگام dequeue؛ وگرنه چندبار وارد queue می‌شود.
- فاصله‌ی BFS تعداد یال است؛ با وزن غلط می‌شود.
- DFS غیربازگشتی فقط با push معکوس با بازگشتی هم‌ترتیب است.
- دور در گراف جهت‌دار سه رنگ می‌خواهد، نه دو.
- ماتریس برای گراف خلوت حافظه هدر می‌دهد: حدود ۱ مگابایت برای ۵۰۰۰ یال.

## تمرین

topological sort را اضافه کنید: DFS سه‌رنگ را به کار ببرید، هر رأس را وقتی سیاه شد به لیست اضافه کنید و لیست را معکوس کنید. بررسی کنید همه‌ی یال‌ها رو به جلو باشند و وجود دور خطا بدهد.
