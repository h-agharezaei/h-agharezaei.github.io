فرض کنید تابعی می‌خواهید که از بین دو عدد کوچک‌تر را برگرداند. برای `int` می‌نویسید `MinInt`. بعد به `float64` هم نیاز پیدا می‌کنید و `MinFloat` را کپی می‌کنید. بعد رشته‌ها. بدنه‌ی هر سه کاملاً یکی است و فقط نوع فرق دارد. راه دیگر این است که پارامترها را `any` بگیرید و در داخل تابع نوع را بررسی کنید، ولی آن‌وقت کامپایلر دیگر نمی‌تواند کمکتان کند و اشتباه‌ها به زمان اجرا می‌روند.

**generics** که از Go 1.18 آمده، این مشکل را حل می‌کند: یک تابع یا نوع می‌نویسید که برای چند نوع کار کند، و کامپایلر همچنان همه‌چیز را چک می‌کند. بعد از [sync، select و context در Go](/fa/posts/go-sync-select-context/) که سراغ همزمانی بودیم، این‌جا می‌بینیم «پارامتر نوع» و «محدودیت» (constraint) چیست، چند تابع و container جنریک می‌نویسیم، به پکیج‌های استاندارد نگاهی می‌اندازیم و آخر هم می‌گوییم کِی بهتر است سراغ generics نرفت.

> همه‌ی مثال‌ها را با Go 1.26 روی macOS (arm64) اجرا کرده‌ام.

## مشکل: یک منطق، چند نوع

این همان وضعیتی است که در ابتدا گفتم. بدون generics دو تابع داریم که فقط نوعشان فرق دارد:

```go
func MinInt(a, b int) int {
	if a < b {
		return a
	}
	return b
}

func MinFloat(a, b float64) float64 { /* identical body */ }
```

(برنامه‌ی کامل هر دو را اجرا کردم و `MinInt(3, 2)` و `MinFloat(1.5, 2.5)` مقدارهای `2` و `1.5` را دادند.) با `any` هم می‌شود یک تابع نوشت، ولی `any` یعنی «هر چیزی»، و روی «هر چیزی» نمی‌شود `<` گذاشت. باید نوع را در زمان اجرا بپرسید (type assertion)، و اگر اشتباه کنید برنامه panic می‌کند، نه کامپایلر. راه سوم **type parameter** است.

## پارامتر نوع و constraint

ایده‌ی اصلی ساده است: همان‌طور که تابع برای مقدارها پارامتر دارد، می‌تواند برای نوع‌ها هم پارامتر داشته باشد. فهرست پارامترهای نوع داخل کروشه می‌آید، قبل از پارامترهای معمولی: `Min[T ...](a, b T) T`. یعنی «تابعی با پارامتر نوع `T`، که دو مقدار از نوع `T` می‌گیرد و یکی از نوع `T` برمی‌گرداند».

ولی کامپایلر باید بداند با `T` چه کارهایی مجاز است. برای همین هر پارامتر نوع یک **constraint** (محدودیت) دارد که می‌گوید چه نوع‌هایی قبول است. چند constraint آماده:

- `any` همه‌چیز را قبول می‌کند. ولی در عوض فقط کارهایی را می‌توانید با آن بکنید که همه‌ی نوع‌ها پشتیبانی می‌کنند (مثلاً نگه‌داشتن و پاس‌دادن، نه مقایسه).
- `comparable` یعنی نوع‌هایی که `==` دارند.
- `cmp.Ordered` از کتاب‌خانه‌ی استاندارد، یعنی نوع‌هایی که با `<` و `>` مرتب می‌شوند (عددها و رشته‌ها). برای `Min` به همین نیاز داریم.

تابع و دو بار استفاده از آن:

```go
func Min[T cmp.Ordered](a, b T) T {
	if a < b {
		return a
	}
	return b
}

fmt.Println(Min(3, 2), Min(1.5, 2.5), Min("b", "a"))
fmt.Println(Min[float64](1, 2.5))
```

```
2 1.5 a
1
```

خط اول سه بار `Min` را برای `int`، `float64` و `string` صدا زده، با یک تابع. لازم نبود بنویسیم `Min[int](3, 2)`، چون کامپایلر نوع را از آرگومان‌ها حدس می‌زند؛ به این **type inference** می‌گویند. خط دوم نوع را صریح داده (`Min[float64](1, 2.5)`)، که باعث شد `1` را هم که ثابت بدون نوع است float بداند و جواب `1` شود. (اگر بخواهید همین کار را در برنامه‌ی واقعی بکنید، Go از نسخه‌ی 1.21 توابع آماده‌ی `min` و `max` دارد؛ `Min` این‌جا برای یاددادن مفهوم است.)

## constraint یک interface است

دیدیم constraint‌های آماده چه هستند. اگر خودتان بخواهید «فقط عددها» را بگویید چه؟ یک constraint سفارشی در Go فقط یک interface است که فهرستی از نوع‌ها دارد. علامت `~` یعنی «هر نوعی که نوع پایه‌اش این است»، پس نوع‌های نام‌دار خودتان هم قبول می‌شوند:

```go
type Number interface {
	~int | ~int64 | ~float64
}

func Sum[T Number](s []T) T {
	var total T
	for _, v := range s {
		total += v
	}
	return total
}

type Cents int

fmt.Println(Sum([]float64{1.5, 2.5}), Sum([]Cents{100, 250}))
```

```
4 350
```

`Sum` یک slice از هر نوعِ عددی می‌گیرد و جمعش را برمی‌گرداند: `1.5 + 2.5` برابر `4`، و برای نوع `Cents` که خودمان تعریف کرده‌ایم `100 + 250` برابر `350`. بدون `~` نوع `Cents` رد می‌شد، چون نوعش `Cents` است نه `int`. (`var total T` مقدار صفر نوع `T` را می‌سازد، یعنی `0`.)

## تابع‌های کمکی جنریک

تابع می‌تواند چند پارامتر نوع داشته باشد. این سه تابع کلاسیک و تابع `Keys` را ببینید:

```go
func Map[T, U any](s []T, f func(T) U) []U { /* ... */ }
func Filter[T any](s []T, keep func(T) bool) []T { /* ... */ }
func Reduce[T, A any](s []T, init A, f func(A, T) A) A { /* ... */ }
func Keys[K comparable, V any](m map[K]V) []K { /* ... */ }
```

`Map` هر عنصر را با تابعی به چیز دیگری (شاید از نوع دیگر) تبدیل می‌کند: ورودی `T` و خروجی `U`. `Filter` فقط عنصرهایی را نگه می‌دارد که تابع `keep` برایشان `true` بدهد. `Reduce` همه را با هم به یک مقدار می‌رساند (مثلاً جمع). `Keys` کلیدهای یک map را برمی‌گرداند. بدنه‌ها ساده‌اند و در برنامه‌ی کامل هستند. استفاده:

```go
nums := []int{1, 2, 3, 4, 5}
fmt.Println(Map(nums, func(n int) string { return "#" + strconv.Itoa(n) }))
fmt.Println(Filter(nums, func(n int) bool { return n%2 == 0 }))
fmt.Println(Reduce(nums, 0, func(a, n int) int { return a + n }))
```

```
[#1 #2 #3 #4 #5]
[2 4]
15
```

خط اول عددها را به رشته تبدیل کرد (`T` برابر `int` و `U` برابر `string`). خط دوم زوج‌ها را نگه داشت. خط سوم همه را جمع زد: ۱۵. کلید map باید `comparable` باشد، برای همین `Keys` همین constraint را روی `K` می‌خواهد. ترتیب پیمایش map تصادفی است، پس اگر کلیدها را چاپ می‌کنید، اول sort کنید؛ در برنامه‌ی کامل با `slices.Sort` این کار را کرده‌ام و `[ali reza sara]` چاپ شد.

## نوع جنریک

نه فقط تابع، نوع هم می‌تواند پارامتر داشته باشد. دو مثال: یک `Stack` (پشته) برای هر نوع، و یک `Set` (مجموعه) که در آن عنصرها باید `comparable` باشند، چون کلید map می‌شوند. متدها پارامتر نوع را فقط تکرار می‌کنند و نمی‌توانند پارامتر جدید اضافه کنند:

```go
type Stack[T any] struct{ items []T }

func (s *Stack[T]) Push(v T) { s.items = append(s.items, v) }

func (s *Stack[T]) Pop() (T, bool) {
	var zero T
	if len(s.items) == 0 {
		return zero, false
	}
	v := s.items[len(s.items)-1]
	s.items = s.items[:len(s.items)-1]
	return v, true
}

type Set[T comparable] map[T]struct{}

func (s Set[T]) Add(v T)      { s[v] = struct{}{} }
func (s Set[T]) Has(v T) bool { _, ok := s[v]; return ok }
```

```
b true
0 false
true false
```

در `main`، سه کار کرده‌ایم. خط اول: `Pop` روی یک `Stack[string]` که `"a"` و `"b"` در آن گذاشته‌ایم؛ آخرین عنصر، `b`، برگشت و `true` یعنی پشته خالی نبود. خط دوم: `Pop` روی `Stack[int]` خالی، که zero value (`0`) و `false` داد. خط سوم: `Has("go")` و `Has("rust")` روی مجموعه‌ای که فقط `"go"` دارد. نکته‌ی `var zero T`: وقتی نوع را نمی‌دانیم، این راه ساختن مقدار صفر آن است. و نوع جنریک را بدون مشخص‌کردن پارامتر نمی‌شود استفاده کرد: باید `Stack[string]` بنویسید.

## کتاب‌خانه‌ی استاندارد موارد رایج را دارد

قبل از اینکه تابع کمکی خودتان را بنویسید، به پکیج‌های `slices`، `maps` و `cmp` نگاه کنید. بسیاری از همین کارها آماده‌اند:

```go
fmt.Println(slices.Contains(nums, 3), slices.Index(nums, 4), slices.Max(nums))
fmt.Println(slices.Sorted(maps.Keys(ages)))
keys := slices.Collect(maps.Keys(ages))
slices.Sort(keys)
fmt.Println(keys)
fmt.Println(cmp.Compare(2, 5))
```

```
true 3 5
[ali reza sara]
[ali reza sara]
-1
```

خط اول: آیا `3` در slice هست (`true`)، `4` در چه اندیسی است (`3`)، و بزرگ‌ترین عنصر چیست (`5`). خط دوم و سوم هر دو کلیدهای مرتب map را می‌دهند، به دو شکل. `cmp.Compare(2, 5)` برابر `-1` است، یعنی اولی کوچک‌تر است. از Go 1.23 به بعد `maps.Keys` یک iterator برمی‌گرداند، نه slice. با `slices.Collect` آن را به slice تبدیل کنید، یا با `slices.Sorted` هم جمع کنید و هم مرتب.

## وقتی constraint رعایت نشود

بزرگ‌ترین مزیت generics نسبت به `any` این است که اشتباه در همان زمان کامپایل پیدا می‌شود. اگر نوعی شرط constraint را نداشته باشد، کامپایلر همان‌جا که تابع را صدا زده‌اید خطا می‌دهد. ما `Min(User{"a"}, User{"b"})` را صدا زدیم، که `User` یک struct است و `<` ندارد:

```
badconstraint/main.go:18:17: User does not satisfy cmp.Ordered (User missing in ~int | ~int8 | ~int16 | ~int32 | ~int64 | ~uint | ~uint8 | ~uint16 | ~uint32 | ~uint64 | ~uintptr | ~float32 | ~float64 | ~string)
```

پیام می‌گوید: `User` شرط `cmp.Ordered` را ندارد، و فهرست نوع‌هایی را می‌دهد که دارند. این خطا در زمان کامپایل است و همین هدف اصلی generics است. (خروجی `go run` یک خط `# example.com/generics/badconstraint` هم در بالا دارد که حذف کرده‌ام.)

## چه زمانی سراغ generics نروید

- **از کد مشخص (concrete) شروع کنید.** اول تابع را برای یک نوع بنویسید. وقتی کاربرد دوم واقعاً آمد، جنریکش کنید.
- **اگر فقط رفتار مهم است، معمولاً interface ساده‌تر است.** `io.Reader` نیازی به پارامتر نوع ندارد، چون فقط می‌خواهیم بخوانیم و برایمان مهم نیست از کجا.
- **فقط برای حذف چند خط تکرار چیزی را جنریک نکنید.** نسخه‌ی جنریک را بخوانید و ببینید فهمیدنش سخت‌تر شده یا نه.
- **متد نمی‌تواند پارامتر نوع مخصوص خودش داشته باشد**؛ فقط خود نوع می‌تواند. اگر به این نیاز دارید، تابع معمولی (نه متد) بنویسید.
- **وقتی type inference شکست بخورد، کامپایلر می‌گوید نمی‌تواند نوع را حدس بزند.** آن‌وقت آرگومان‌های نوع را صریح بدهید.

## تمرین

۱. تابع `Max[T cmp.Ordered](s []T) (T, bool)` را بنویسید که برای slice خالی `false` برگرداند.
۲. به `Stack[T]` متدهای `Len() int` و `Peek() (T, bool)` اضافه کنید.
۳. تابع `Uniq[T comparable](s []T) []T` را با استفاده از `Set[T]` بنویسید که تکراری‌ها را حذف کند و ترتیب را نگه دارد.
