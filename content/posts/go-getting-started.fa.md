فرض کنید برنامه‌ای نوشته‌اید که یک متغیر تعریف می‌کند و هیچ‌جا از آن استفاده نمی‌کند. در بسیاری از زبان‌ها در بدترین حالت یک هشدار می‌گیرید. در Go برنامه اصلاً ساخته نمی‌شود. از همان برنامه‌ی اول، Go همین‌قدر سخت‌گیر است: import یا متغیر محلیِ بی‌استفاده خطای کامپایل است، نه هشدار، و شکل ظاهری کد را ابزاری به اسم `go fmt` تعیین می‌کند، نه سلیقه‌ی تیم.

این مقاله اولین مقاله‌ی سری **Go Fundamentals** است و از صفر شروع می‌کند. اول مبانی خود زبان را می‌گذرانیم، و بعد یک سری دوم می‌آید که روی بک‌اند تمرکز دارد: سرویس‌های HTTP، دیتابیس و هم‌روندی در سیستم‌های واقعی. قبلاً در مقاله‌ای درباره‌ی [NATS JetStream](/fa/posts/nats-jetstream-go/) از Go استفاده کرده بودم، ولی آن‌جا فرض کرده بودم کد Go می‌خوانید. این‌جا این فرض را کنار می‌گذارم.

هدف امروز ساده است: Go را نصب کنیم، یک ماژول بسازیم، یک برنامه‌ی کوچک بنویسیم و چند دستوری را یاد بگیریم که هر روز تایپ خواهید کرد. مثال‌های این مقاله را با Go 1.26.0 روی macOS (معماری arm64) اجرا کرده‌ام.

## چرا Go برای بک‌اند

Go زبانی است که **کامپایلی** است (کد را پیش از اجرا به برنامه‌ی ماشین تبدیل می‌کنند) و **تایپ ایستا** دارد (نوع هر متغیر هنگام کامپایل معلوم است و خطای نوع همان‌جا گرفته می‌شود). مشخصات زبان هم کوچک است و می‌شود همه‌اش را یاد گرفت. چند دلیل که آدم‌ها برای بک‌اند انتخابش می‌کنند:

- `go build` یک فایل باینری واحد می‌سازد. پس استقرار و ساخت ایمیج Docker ساده می‌شود: فقط همان یک فایل را جابه‌جا می‌کنید.
- هم‌روندی، یعنی انجام چند کار با هم، بخشی از خود زبان است (با goroutine و channel که در مقاله‌های بعد می‌بینیم).
- کتاب‌خانه‌ی استاندارد HTTP، JSON، تست و خیلی چیزهای دیگر را پوشش می‌دهد.
- ابزارها (فرمت‌کننده، اجراکننده‌ی تست، مدیریت وابستگی) همراه خود زبان می‌آیند. تیم‌ها کمتر سر تنظیمات بحث می‌کنند.

## نصب

راهنمای رسمی در [go.dev/doc/install](https://go.dev/doc/install) است. روی macOS اگر Homebrew دارید، `brew install go` هم یک گزینه است. بعد از نصب، بررسی کنید که همه‌چیز سر جایش است:

```bash
go version
```

```
go version go1.26.0 darwin/arm64
```

خروجی نسخه‌ی Go، سیستم‌عامل و معماری پردازنده را نشان می‌دهد. روی سیستم شما احتمالاً عددهای دیگری می‌بینید.

## اولین ماژول

کد Go همیشه داخل یک **ماژول** (module) قرار می‌گیرد. ماژول یعنی یک پوشه که فایلی به اسم `go.mod` دارد. این فایل به Go می‌گوید این پوشه یک پروژه است، اسمش چیست و چه چیزهایی لازم دارد. یکی بسازیم:

```bash
mkdir hello && cd hello
go mod init example.com/hello
```

عبارت `example.com/hello` **مسیر ماژول** است، یعنی اسمی که کدهای دیگر برای import کردن شما به کار می‌برند. برای آزمایش محلی هر اسمی جواب می‌دهد. برای چیزی که منتشر می‌کنید معمولاً آدرس مخزن کد را می‌گذارند.

حالا فایل `main.go` را می‌نویسیم:

```go
package main

import "fmt"

func main() {
	fmt.Println("Hello, Go!")
}
```

این کد سه بخش دارد. `package main` می‌گوید این فایل یک برنامه‌ی اجرایی است (نه یک کتاب‌خانه). `import "fmt"` بسته‌ی `fmt` از کتاب‌خانه‌ی استاندارد را می‌آورد که چاپ و قالب‌بندی متن را انجام می‌دهد. و تابع `main` نقطه‌ی شروع برنامه است. اجرایش کنید:

```bash
go run .
```

```
Hello, Go!
```

نقطه‌ی بعد از `go run` یعنی «پکیجِ همین پوشه». `go run` برنامه را در یک مسیر موقت کامپایل و بلافاصله اجرا می‌کند و چیزی در پوشه‌ی شما باقی نمی‌گذارد. اگر می‌خواهید خود فایل باینری را داشته باشید، از `go build` استفاده کنید:

```bash
go build -o hello .
./hello
```

```
Hello, Go!
```

گزینه‌ی `-o hello` اسم فایل خروجی را مشخص می‌کند. فایل `hello` یک برنامه‌ی مستقل است و برای اجرا به نصب‌بودن Go نیاز ندارد.

## داخل go.mod چیست

فایلی که `go mod init` ساخت این‌طور است:

```
module example.com/hello

go 1.25.0
```

فقط دو چیز دارد: مسیر ماژول، و یک خط `go` با نسخه‌ی Go که ماژول انتظارش را دارد. وقتی وابستگی اضافه کنید، خط‌های `require` هم این‌جا ظاهر می‌شوند.

یک نکته‌ی جالب: ابزار من نسخه‌ی 1.26.0 بود، ولی `go mod init` عدد `go 1.25.0` را نوشت. یعنی این خط نسخه‌ی زبانِ مورد انتظار ماژول را ثبت می‌کند و لزوماً نسخه‌ی دقیق ابزار نصب‌شده نیست.

## یک برنامه‌ی کمی بزرگ‌تر

حالا می‌خواهیم برنامه کمی کار کند: یک نام اختیاری را از خط فرمان بگیرد و اگر نام ندادیم، به‌جایش `world` بگذارد.

```go
package main

import (
	"fmt"
	"os"
)

// greeting builds the message for a given name.
func greeting(name string) string {
	return fmt.Sprintf("Hello, %s!", name)
}

func main() {
	name := "world"
	if len(os.Args) > 1 {
		name = os.Args[1]
	}
	fmt.Println(greeting(name))
}
```

بیایید آرام بخوانیمش. تابع `greeting` یک `string` می‌گیرد و پیام خوش‌آمدگویی را به‌صورت `string` برمی‌گرداند؛ `fmt.Sprintf` مثل `Println` است، با این فرق که متن را چاپ نمی‌کند و برمی‌گرداند. در `main`، اول `name` را `"world"` می‌گذاریم. `os.Args` فهرست آرگومان‌های خط فرمان است و عنصر شماره‌ی صفرش خود برنامه است، پس اولین آرگومان واقعی در ایندکس ۱ قرار دارد. اگر آرگومانی داده شده باشد (`len(os.Args) > 1`)، `name` را با آن عوض می‌کنیم. تعریف متغیر با `:=` و دستور `if` را در مقاله‌ی بعد درست‌وحسابی توضیح می‌دهم؛ فعلاً همین قدر کافی است که همان‌طور که انتظار دارید کار می‌کنند.

برنامه را یک بار بدون آرگومان و یک بار با آرگومان اجرا می‌کنیم:

```bash
go run .
go run . Roham
```

```
Hello, world!
Hello, Roham!
```

اجرای اول آرگومانی ندارد، پس نام پیش‌فرض می‌آید. در اجرای دوم، `Roham` اولین آرگومان است و جای `world` را می‌گیرد.

## دستورهای روزمره

برنامه‌نویسی با Go روی چند دستور ثابت می‌چرخد. این‌ها را باید از حفظ باشید:

- `go fmt ./...` فایل‌ها را به قالب استاندارد درمی‌آورد و اسم فایل‌هایی را که عوض کرده چاپ می‌کند. در دنیای Go کسی سر سبک کدنویسی بحث نمی‌کند، چون فرمت‌کننده تصمیم می‌گیرد. (`./...` یعنی «همین پوشه و همه‌ی زیرپوشه‌ها».)
- `go vet ./...` کدهایی را گزارش می‌دهد که کامپایل می‌شوند ولی مشکوک‌اند. اگر مشکلی نباشد، هیچ‌چیز چاپ نمی‌کند.
- `go test ./...` تست‌ها را اجرا می‌کند. تست در Go تابعی است به شکل `TestXxx(t *testing.T)` که در فایلی با پسوند `_test.go` می‌نویسید. برای تابع `greeting` بالا:

```go
package main

import "testing"

func TestGreeting(t *testing.T) {
	got := greeting("Roham")
	want := "Hello, Roham!"
	if got != want {
		t.Fatalf("got %q, want %q", got, want)
	}
}
```

```
$ go test ./...
ok  	example.com/greet	0.273s
```

تست نتیجه‌ی واقعی را با نتیجه‌ی مورد انتظار مقایسه می‌کند و اگر فرق داشتند، با `t.Fatalf` شکست می‌خورد. خط `ok` یعنی همه‌ی تست‌های آن پکیج گذشتند؛ عدد آخر زمان اجراست و هر بار کمی فرق می‌کند. اسم `example.com/greet` به این خاطر است که این تست را در ماژولی به همین نام اجرا کردم.

- `go mod tidy` وابستگی‌های جاافتاده را به `go.mod` اضافه می‌کند و بی‌استفاده‌ها را حذف می‌کند. وقتی هیچ وابستگی‌ای نداریم، مثل این‌جا، چیزی عوض نمی‌شود.

`go fmt` را هم با یک فایل عمداً بدفرمت امتحان کردم: اسم `bad.go` را چاپ کرد و `func  x( ){ }` را به `func x() {}` تبدیل کرد.

## Go چیزها را کجا نگه می‌دارد

وقتی برای اولین بار وابستگی‌ای دانلود می‌کنید، می‌پرسید کجا رفت. این دستور جواب را می‌دهد:

```bash
go env GOPATH GOMODCACHE
```

```
/home/user/go
/home/user/go/pkg/mod
```

مسیرها به سیستم‌عامل و نام کاربری شما بستگی دارند (مثلاً در macOS چیزی شبیه `/Users/you/go` است)، پس این‌جا یک نمونه‌ی ساختگی گذاشته‌ام. `GOMODCACHE` جایی است که وابستگی‌های دانلودشده ذخیره می‌شوند و بین همه‌ی پروژه‌های شما مشترک است. به‌طور پیش‌فرض زیر `GOPATH` قرار دارد. لازم نیست کد خودتان را آن‌جا بگذارید؛ پروژه‌ها هر جا که بخواهید می‌توانند باشند.

## خطاهای رایج در روز اول

- `go run main.go` فقط همان یک فایل را کامپایل می‌کند. وقتی بیش از یک فایل دارید، تابعی که در فایل دیگر تعریف شده پیدا نمی‌شود. به‌جایش `go run .` را بزنید تا کل پکیج ساخته شود.
- دستورها را از داخل ماژول، یعنی کنار `go.mod`، اجرا کنید. وگرنه خطایی می‌گیرید که می‌گوید `go.mod` پیدا نشد.
- import یا متغیر محلیِ بی‌استفاده خطای کامپایل است. اگر موقع آزمایش یک متغیر را موقتاً استفاده نمی‌کنید، باید حذفش کنید یا بعداً استفاده‌اش کنید.
- `go build` باینری را در پوشه‌ی جاری می‌نویسد. آن را commit نکنید.
- موفق‌بودن `go vet` یعنی کد از چند اشتباه رایج دور است، نه اینکه درست کار می‌کند. درستی را تست‌ها نشان می‌دهند.

## تمرین

۱. یک ماژول تازه بسازید و برنامه‌ی خوش‌آمدگویی را طوری تغییر دهید که دو آرگومان (نام و نام خانوادگی) بگیرد و `Hello, First Last!` چاپ کند.
۲. منطق نام پیش‌فرض `world` را در یک تابع جدا بگذارید و برایش تست دوم بنویسید.
۳. پیش از تمام‌شدن، `go fmt` و `go vet` و `go test` را اجرا کنید.
