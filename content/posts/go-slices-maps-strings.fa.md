فرض کنید فهرستی از پنج عدد دارید و از وسطش یک تکه جدا می‌کنید تا رویش کار کنید. انتظار دارید فهرست اصلی دست‌نخورده بماند. در Go اغلب این‌طور نیست: `b := a[1:3]` نسخه‌ای از عنصرها نمی‌سازد، و اگر بعدش روی `b` تابع `append` را صدا بزنید، ممکن است بی‌سروصدا عنصری از `a` را بازنویسی کند. یک مثال دیگر: `len("سلام")` برابر ۸ است، نه ۴.

**slice**، **map** و **string** تقریباً در هر برنامه‌ی Go استفاده می‌شوند و هر کدام رفتاری دارند که تازه‌کارها را غافلگیر می‌کند. بعد از [توابع، `defer` و مدیریت خطا](/fa/posts/go-functions-defer-errors/) و [نوع‌ها، متغیرها و کنترل جریان](/fa/posts/go-types-control-flow/)، این سه نوع را با اجرای کد و خروجی واقعی بررسی می‌کنیم، نه با حدس و شهود.

> همه‌ی کدها با Go 1.26 و به‌صورت یک مثال محلی اجرا شده‌اند. مقدار دقیق رشد `cap` جزئیات پیاده‌سازی است و تضمین زبان نیست.

## آرایه و slice

اول دو واژه را از هم جدا کنیم. **آرایه** ردیفی از خانه‌هاست که تعدادش ثابت است و در نوع آرایه هم می‌آید: `[3]int` یعنی سه عدد صحیح، و `[4]int` نوع دیگری است. آرایه را وقتی به متغیر دیگری بدهید، کپی می‌شود.

**Slice** چیز دیگری است. آن را مثل یک «پنجره» روی یک ردیف خانه تصور کنید: خودش داده ندارد و فقط نشان می‌دهد از کدام آرایه، از کدام خانه شروع می‌کنید و چند خانه می‌بینید. در عمل slice یک هدر کوچک با سه فیلد است: اشاره‌گر به یک آرایه‌ی پشتیبان (**backing array**)، `len` (چند عنصر را می‌بینید) و `cap` (از همین نقطه تا آخر آرایه‌ی پشتیبان چند خانه هست). تقریباً همیشه با slice کار می‌کنید و نه با آرایه.

این کد فرق را نشان می‌دهد و هم رشد یک slice را با `append`:

```go
arr := [3]int{1, 2, 3}
b := arr // آرایه کپی می‌شود
b[0] = 99
fmt.Println(arr, b)

var s []int
for i := 0; i < 10; i++ {
    s = append(s, i)
    fmt.Printf("len=%d cap=%d\n", len(s), cap(s))
}
```

```
[1 2 3] [99 2 3]
len=1 cap=4
len=2 cap=4
len=3 cap=4
len=4 cap=4
len=5 cap=8
...
len=9 cap=16
len=10 cap=16
```

خط اول نشان می‌دهد `b` کپی مستقل است: عوض‌کردن `b[0]` به `arr` کاری ندارد. بقیه‌ی خروجی رشد slice است (در خروجی بالا چند خط وسط را حذف کرده‌ام). هر بار `append` یک عنصر اضافه می‌کند و `len` یکی بالا می‌رود. `cap` ثابت می‌ماند تا وقتی که جا تمام شود. در `len=5` ظرفیت از ۴ به ۸ می‌پرد، و در `len=9` از ۸ به ۱۶: Go یک آرایه‌ی بزرگ‌تر ساخته و داده‌ها را به آن کپی کرده است. برای همین باید همیشه بنویسید `s = append(s, ...)`؛ نتیجه ممکن است به آرایه‌ی دیگری اشاره کند. (عددهای دقیق رشد جزئیات پیاده‌سازی است و تضمین زبان نیست.)

## مشکل کلاسیک: backing array مشترک

حالا به مثالی برسیم که در ابتدا گفتم. برش‌زدن (slicing) داده را کپی نمی‌کند، فقط یک پنجره‌ی تازه روی همان آرایه می‌سازد. پس دو slice می‌توانند به یک حافظه نگاه کنند. قدم‌به‌قدم ببینیم چه می‌شود:

```go
a := []int{1, 2, 3, 4, 5}
b := a[1:3]
fmt.Println(b, len(b), cap(b))
b[0] = 99
fmt.Println(a, b)
b = append(b, 77) // در cap جا می‌شود: a[3] بازنویسی می‌شود
fmt.Println(a, b)
c := append(a[:2:2], 1000) // full slice expression آرایه‌ی جدید می‌سازد
c[0] = -1
fmt.Println(a, c)
```

```
[2 3] 2 4
[1 99 3 4 5] [99 3]
[1 99 3 77 5] [99 3 77]
[1 99 3 77 5] [-1 99 1000]
```

- **خط اول:** `b := a[1:3]` عنصرهای شماره‌ی ۱ و ۲ از `a` را نشان می‌دهد، یعنی `[2 3]` با `len` برابر ۲. `cap` برابر ۴ است، چون از خانه‌ی ۱ تا آخر `a` چهار خانه هست.
- **خط دوم:** `b[0] = 99` را نوشتیم، ولی `a` هم عوض شد: `a[1]` حالا ۹۹ است. `b[0]` و `a[1]` یک خانه‌اند.
- **خط سوم:** بدتر از آن. `b` فقط دو عنصر دارد ولی ظرفیت ۴. وقتی `append(b, 77)` را صدا می‌زنیم، جای خالی در ظرفیت هست، پس Go آرایه‌ی جدیدی نمی‌سازد و عدد ۷۷ را در خانه‌ی بعد از `b` می‌نویسد. آن خانه `a[3]` است. نتیجه: `a[3]` بی‌سروصدا از ۴ به ۷۷ بدل شد.
- **خط آخر:** شکل سه‌اندیسی `a[:2:2]` ظرفیت را هم محدود می‌کند: دو عنصر با ظرفیت ۲. پس `append` جای خالی ندارد و مجبور است آرایه‌ی تازه‌ای بسازد. `c` روی آرایه‌ی جدید است، و `c[0] = -1` دیگر به `a` دست نمی‌زند: `a` همان `[1 99 3 77 5]` می‌ماند.

نتیجه‌ی عملی: اگر می‌خواهید زیر-slice روی داده‌ی اصلی اثر نگذارد، یا باید `copy` کنید (در بخش بعد)، یا ظرفیت را با `a[:n:n]` محدود کنید.

## copy، make و تفاوت nil با خالی

سه چیز کوچک که باید بشناسید. `make([]int, 2, 5)` یک slice با `len` برابر ۲ و `cap` برابر ۵ می‌سازد که همه‌ی عنصرهایش مقدار صفرند. `copy(dst, src)` عنصرها را به slice دیگری کپی می‌کند و تعداد کپی‌شده را برمی‌گرداند. و slice از نوع `nil` با slice خالی فرق ظریفی دارد:

```go
var nilS []int
empty := []int{}
fmt.Println(nilS == nil, empty == nil, len(nilS), len(empty))

m := make([]int, 2, 5) // len 2, cap 5
fmt.Println(m, len(m), cap(m))

src := []int{1, 2, 3}
dst := make([]int, len(src))
n := copy(dst, src)
dst[0] = 100
fmt.Println(n, src, dst)
```

```
true false 0 0
[0 0] 2 5
3 [1 2 3] [100 2 3]
```

خط اول: هر دو slice طولشان ۰ است، ولی فقط اولی با `nil` برابر است. در عمل هر دو با `append` و `range` کار می‌کنند و فقط در مقایسه‌ی مستقیم با `nil` فرق دارند. خط دوم همان slice `make` است: دو صفر و ظرفیت ۵. خط سوم: `copy` سه عنصر را کپی کرد (مقدار برگشتی ۳)، و چون `dst` آرایه‌ی خودش را دارد، عوض‌کردن `dst[0]` به `src` کاری ندارد.

## Map

**Map** جدولی از کلید به مقدار است. این مثال ساختن، خواندن، حذف و کپی‌کردن map را نشان می‌دهد:

```go
ages := map[string]int{"ali": 30, "sara": 25}
ages["reza"] = 41
v, ok := ages["nobody"]
fmt.Println(v, ok)
if age, ok := ages["sara"]; ok {
    fmt.Println("sara", age)
}
delete(ages, "ali")
delete(ages, "ghost") // بدون اثر
fmt.Println(len(ages), ages)

alias := ages
alias["sara"] = 26
fmt.Println(ages["sara"])
```

```
0 false
sara 25
2 map[reza:41 sara:25]
26
```

وقتی کلیدی در map نباشد، خواندنش مقدار صفر نوع مقدار را برمی‌گرداند (اینجا `0`)، نه خطا. پس چطور بفهمیم «کلید نیست» با «مقدارش واقعاً صفر است» فرق دارد؟ با فرم دو-مقداری که به آن **comma-ok** می‌گویند: `v, ok := ages["nobody"]`. `ok` می‌گوید کلید وجود داشت یا نه. خط اول خروجی همین است: `0 false`. خط دوم از همین الگو در یک `if` استفاده می‌کند. بعد `delete` را می‌بینید: حذف `"ali"` کلید را برمی‌دارد و حذف کلید ناموجود (`"ghost"`) اتفاقی نمی‌اندازد؛ برای همین `len` در خط سوم ۲ است.

خط آخر: `alias := ages` یک map جدید نمی‌سازد، فقط اشاره به همان map را کپی می‌کند. پس با تغییر `alias["sara"]` مقدار `ages["sara"]` هم ۲۶ می‌شود.

در مقاله‌های قبل دیدیم که خواندن از map برابر `nil` مشکلی ندارد، اما نوشتن panic می‌دهد:

```go
var m map[string]int
m["a"] = 1
```

```
panic: assignment to entry in nil map
```

map را همیشه با `make` یا literal (مثل `map[string]int{}`) بسازید.

یک چیز دیگر: ترتیب پیمایش map مشخص نیست، و Go عمداً آن را هر بار تصادفی می‌کند تا کسی به ترتیب خاصی تکیه نکند. من یک map هشت‌کلیدی را در دو اجرا پیمایش کردم و یک بار `0 1 2 3 4 5 6 7` و بار دیگر `6 7 0 1 2 3 4 5` گرفتم. موقع بازنویسی این مقاله هم همان برنامه را دوباره اجرا کردم و ترتیب‌های دیگری، مثل `1 2 3 4 5 6 7 0` و `3 4 5 6 7 0 1 2`، دیدم. هیچ‌وقت به ترتیب تکیه نکنید.

## String

در مقاله‌ی نوع‌ها دیدیم string دنباله‌ای تغییرناپذیر از بایت‌هاست، معمولاً UTF-8، و `len` بایت می‌شمارد. حالا کنار هم می‌گذاریمشان: `utf8.RuneCountInString` تعداد کاراکتر (**rune**) را می‌دهد و `range` روی string، rune به rune جلو می‌رود. سه کلمه را امتحان می‌کنیم، یکی انگلیسی، یکی فارسی و یکی یک ایموجی:

```go
for _, w := range []string{"hello", "سلام", "🚀"} {
    fmt.Println(w, len(w), utf8.RuneCountInString(w))
}
for i, r := range "سلام" {
    fmt.Printf("%d:%c(%U) ", i, r, r)
}
```

```
hello 5 5
سلام 8 4
🚀 4 1
0:س(U+0633) 2:ل(U+0644) 4:ا(U+0627) 6:م(U+0645)
```

برای هر کلمه دو عدد داریم: تعداد بایت و تعداد rune. `hello` هر دو ۵ است، چون هر حرف انگلیسی یک بایت است. کلمه‌ی فارسی ۴ rune ولی ۸ بایت دارد، و موشک ۱ rune ولی ۴ بایت. خط آخر اندیس و کد یونیکد هر حرف `سلام` را نشان می‌دهد (`%c` خود حرف و `%U` کدش). اندیس‌ها دوتا‌دوتا جلو می‌روند (۰ و ۲ و ۴ و ۶)، چون هر حرف دو بایت جا می‌گیرد.

نتیجه: `s[0]` یک بایت می‌دهد، نه یک کاراکتر. برای `"سلام"` همین عبارت عدد ۲۱۶ را داد، که بایت اول حرف «س» است.

حالا ساختن string. چون string تغییرناپذیر است، چسباندن مداوم به آن در یک حلقه هر بار یک string تازه می‌سازد. برای ساختن متن در حلقه از `strings.Builder` استفاده کنید. سه تابع پرکاربرد را هم بشناسید: `Split` متن را با یک جداکننده تکه‌تکه می‌کند، `Join` برعکس، و `Fields` روی فاصله‌ها می‌شکند:

```go
var sb strings.Builder
for i := 0; i < 3; i++ {
    fmt.Fprintf(&sb, "item%d,", i)
}
sb.WriteString("end")
fmt.Println(sb.String())

parts := strings.Split("a,b,,c", ",")
fmt.Printf("%q\n", parts)
fmt.Println(strings.Join(parts, "-"))
fmt.Printf("%q\n", strings.Fields("  go   is \t fun\n"))
```

```
item0,item1,item2,end
["a" "b" "" "c"]
a-b--c
["go" "is" "fun"]
```

`Builder` سه بار `item…,` و بعد `end` را پشت هم می‌چسباند و یک بار در آخر رشته را بیرون می‌دهد. `Split` روی `"a,b,,c"` چهار تکه می‌دهد، و تکه‌ی خالی بین دو ویرگول را هم نگه می‌دارد؛ برای همین `Join` با `-` خروجی `a-b--c` می‌دهد. `Fields` روی هر دنباله از فاصله، تب و خط جدید می‌شکند و خالی‌ها را حذف می‌کند، پس از آن متن به‌ظاهر شلوغ فقط سه کلمه می‌ماند.

## برنامه‌ی کوچک: شمارش تکرار کلمه

حالا سه نوع را با هم به کار ببریم. می‌خواهیم ببینیم هر کلمه در یک جمله چند بار آمده است. map کلمه را به تعداد می‌رساند. ولی چون ترتیب map مشخص نیست، برای چاپ مرتب کلیدها را در یک slice می‌ریزیم و مرتب می‌کنیم:

```go
text := "the quick brown fox jumps over the lazy dog the fox"
counts := map[string]int{}
for _, w := range strings.Fields(strings.ToLower(text)) {
    counts[w]++
}
keys := make([]string, 0, len(counts))
for k := range counts {
    keys = append(keys, k)
}
sort.Slice(keys, func(i, j int) bool {
    if counts[keys[i]] != counts[keys[j]] {
        return counts[keys[i]] > counts[keys[j]]
    }
    return keys[i] < keys[j]
})
for _, k := range keys {
    fmt.Printf("%-6s %d\n", k, counts[k])
}
```

```
the    3
fox    2
brown  1
dog    1
jumps  1
lazy   1
over   1
quick  1
```

`counts[w]++` از مقدار صفرِ کلید ناموجود استفاده می‌کند: اولین بار که کلمه‌ای می‌آید، مقدارش ۰ است و می‌شود ۱. بعد از شمردن، کلیدها را در `keys` می‌ریزیم و با `sort.Slice` و یک تابع مقایسه مرتب می‌کنیم: اول بر اساس تعداد (از زیاد به کم)، و اگر تعداد برابر بود، الفبایی. خروجی هم همین را نشان می‌دهد: `the` سه بار، `fox` دو بار، و بقیه یک بار به ترتیب الفبا. و چون ترتیب را خودمان با sort مشخص کرده‌ایم، خروجی در هر اجرا یکی است.

## جاهایی که slice و map غافلگیرتان می‌کنند

- **نتیجه‌ی `append` را همیشه انتساب بدهید** (`s = append(s, x)`)، و یادتان باشد که نتیجه ممکن است با slice اصلی حافظه‌ی مشترک داشته باشد یا نداشته باشد، بسته به اینکه جا بوده یا نه.
- **زیر-slice‌ها backing array را share می‌کنند.** برای استقلال از `copy` یا `a[:n:n]` استفاده کنید.
- **نوشتن در map نوع nil panic می‌دهد، خواندن نه.**
- **به ترتیب پیمایش map تکیه نکنید.** برای خروجی ثابت، کلیدها را مرتب کنید.
- **`len(s)` بایت است، نه کاراکتر.** برای متن از `utf8.RuneCountInString` یا `range` استفاده کنید.
