فرض کنید تعداد کالا ۳ تا و قیمت هر کدام ۲٫۵ است و می‌خواهید جمع را حساب کنید. در بیشتر زبان‌ها `count * price` را می‌نویسید و ۷٫۵ می‌گیرید. در Go همین یک خط اصلاً کامپایل نمی‌شود. Go نمی‌خواهد حدس بزند که شما با `int` کار می‌کنید یا با عدد اعشاری، و از شما می‌خواهد خودتان تصمیم را بنویسید.

همین سخت‌گیری در بقیه‌ی پایه‌های زبان هم دیده می‌شود. هر متغیر یک مقدار شروع مشخص دارد، متغیری که استفاده نشود خطای کامپایل می‌دهد و فقط یک حلقه داریم، یعنی `for`. Go در این بخش ابزار کمتری از بیشتر زبان‌ها دارد و این انتخاب عمدی است: وقتی هر کار فقط یک راه دارد، خواندن کد دیگران ساده‌تر می‌شود. اگر هنوز Go را نصب نکرده‌اید، از [شروع کار با Go](/fa/posts/go-getting-started/) شروع کنید.

> همه‌ی مثال‌های زیر با Go 1.26.0 روی macOS اجرا شده‌اند و خروجی‌ها از همان اجراها برداشته شده‌اند.

## var و :=

برای تعریف متغیر دو راه داریم:

```go
var count int = 3   // صریح
var name = "Roham"  // نوع از روی مقدار حدس زده می‌شود
price := 2.5        // فرم کوتاه، فقط داخل تابع
```

خط اول نوع را صریح می‌گوید. در خط دوم Go نوع را از روی مقدار می‌فهمد (به این کار می‌گویند **استنباط نوع**): `"Roham"` یک رشته است، پس `name` از نوع `string` می‌شود. خط سوم فرم کوتاه است: `:=` هم متغیر را تعریف می‌کند و هم مقدار می‌دهد. داخل تابع تقریباً همیشه همین را می‌نویسید. بیرون از تابع، یعنی در سطح package، فقط `var` کار می‌کند.

یک قاعده را از همین‌جا به خاطر بسپارید: متغیر محلیِ استفاده‌نشده خطای کامپایل است، نه هشدار.

## Zero value

در بعضی زبان‌ها (مثل C) متغیری که مقدار نگرفته باشد ممکن است محتوای تصادفی حافظه را داشته باشد. در Go چنین چیزی نداریم. متغیری که بدون مقدار تعریف شود، **مقدار صفرِ** نوعش را می‌گیرد؛ به انگلیسی به آن **zero value** می‌گویند. صفر برای عددها، رشته‌ی خالی برای `string`، `false` برای `bool`، و `nil` (یعنی «هیچ‌چیز») برای اشاره‌گر و slice و map.

برای دیدنش یک متغیر از هر نوع می‌سازیم و بدون مقداردادن چاپشان می‌کنیم:

```go
var i int
var s string
var b bool
var f float64
var p *int
var sl []int
var m map[string]int

fmt.Printf("int:     %v\n", i)
fmt.Printf("string:  %q\n", s)
fmt.Printf("bool:    %v\n", b)
fmt.Printf("float64: %v\n", f)
fmt.Printf("pointer: %v\n", p)
fmt.Printf("slice:   %v (nil: %t, len: %d)\n", sl, sl == nil, len(sl))
fmt.Printf("map:     %v (nil: %t, len: %d)\n", m, m == nil, len(m))
```

```text
int:     0
string:  ""
bool:    false
float64: 0
pointer: <nil>
slice:   [] (nil: true, len: 0)
map:     map[] (nil: true, len: 0)
```

در `Printf`، `%v` یعنی «مقدار را به شکل پیش‌فرض بنویس»، `%q` یعنی «رشته را با گیومه بنویس» (برای همین رشته‌ی خالی را `""` می‌بینیم و می‌فهمیم واقعاً خالی است) و `%t` برای `bool` است. خروجی نشان می‌دهد هر نوع مقدار صفر خودش را دارد. دو خط آخر جالب‌ترند: slice و map بدون مقدار، `nil` هستند، ولی طولشان صفر است و مثل مقدار خالی چاپ می‌شوند.

این ویژگی دسته‌ی کاملی از باگ‌ها را حذف می‌کند، چون هیچ متغیری «نامشخص» نیست. یک نکته‌ی عملی: slice با مقدار `nil` هم قابل استفاده است (`len` و `append` روی آن کار می‌کنند)، پس معمولاً لازم نیست دستی مقداردهی‌اش کنید. map فرق دارد و در بخش «دام‌های رایج» به آن برمی‌گردیم.

## نوع‌های پایه

بیایید نوع‌هایی را که بیشتر از همه می‌بینید مرور کنیم:

- **عددهای صحیح:** `int` و `uint` (بدون علامت) هم‌اندازه‌ی معماری سیستم‌اند؛ روی سیستم من ۶۴ بیت. نوع‌هایی با اندازه‌ی مشخص هم داریم، مثل `int8` و `int32` و `int64`. اگر دلیل خاصی ندارید، از همان `int` استفاده کنید.
- **اعشاری:** `float64` پیش‌فرض است. `float32` هم هست ولی کم لازم می‌شود.
- **`string`:** دنباله‌ای تغییرناپذیر از بایت‌ها، که معمولاً به‌صورت UTF-8 است. دو اسم مستعار هم مهم‌اند: `byte` نام دیگر `uint8` است و `rune` نام دیگر `int32` که یک code point یونیکد، یعنی یک «نویسه» را نگه می‌دارد.

فرق بایت و rune تا وقتی فقط انگلیسی می‌نویسید خودش را نشان نمی‌دهد. به محض اینکه از ASCII بیرون بروید، مهم می‌شود. این مثال را ببینید:

```go
s := "سلام"
fmt.Println(len(s), len([]rune(s)))   // 8 4

for i, r := range "hé" {
    fmt.Println(i, r, string(r))
}
// 0 104 h
// 1 233 é

fmt.Println([]byte("hé"))
// [104 195 169]
```

در خط اول `len(s)` بایت‌ها را می‌شمارد و ۸ می‌دهد، ولی `"سلام"` چهار حرف دارد. هر حرف فارسی در UTF-8 دو بایت جا می‌گیرد. اگر رشته را به `[]rune` تبدیل کنیم، هر عنصر یک نویسه است و `len` عدد ۴ را می‌دهد.

حلقه‌ی `range` روی رشته نویسه‌به‌نویسه (rune به rune) جلو می‌رود. در هر دور دو چیز می‌دهد: جای شروع آن rune در رشته (به بایت) و خود rune. در `"hé"`، حرف `h` یک بایت است و از جای ۰ شروع می‌شود و `é` از جای ۱. کد یونیکد `h` عدد ۱۰۴ است و `é` عدد ۲۳۳. خط آخر نشان می‌دهد چرا: `[]byte("hé")` سه بایت دارد، یکی برای `h` و دو تا برای `é`. پس `len("hé")` برابر ۳ است، نه ۲.

## ثابت‌ها و iota

ثابت‌ها با `const` تعریف می‌شوند و مقدارشان بعد از تعریف عوض نمی‌شود. وقتی چند مقدار مرتبط دارید، مثلاً روزهای هفته، نوشتن عددها با دست خسته‌کننده است و راحت اشتباه می‌شود. برای این کار **iota** را داریم: شمارنده‌ای که در هر بلوک `const` از صفر شروع می‌کند و در هر خط یکی زیاد می‌شود. وقتی از خط دوم به بعد چیزی ننویسید، Go همان عبارت خط قبل را تکرار می‌کند:

```go
type Weekday int

const (
    Sunday Weekday = iota
    Monday
    Tuesday
)

const (
    _  = iota
    KB = 1 << (10 * iota)
    MB
    GB
)
```

در بلوک اول، `Sunday` برابر ۰ است، `Monday` برابر ۱ و `Tuesday` برابر ۲. در بلوک دوم، خط اول با `_` عدد ۰ را دور می‌اندازد. بعد `KB` برابر `1 << (10 * 1)` است، یعنی ۱ که ۱۰ بیت به چپ رفته (همان ۱۰۲۴). `MB` همین عبارت را با iota برابر ۲ تکرار می‌کند (`1 << 20`) و `GB` با ۳ (`1 << 30`). چاپ `Sunday, Monday, Tuesday` خروجی `0 1 2` می‌دهد و چاپ `KB, MB, GB` خروجی `1024 1048576 1073741824`.

## تبدیل ضمنی نداریم

برگردیم به همان مثالی که با آن شروع کردیم. در Go بین نوع‌های عددی هیچ تبدیل خودکاری انجام نمی‌شود. اگر `int` و `float64` را می‌خواهید با هم ترکیب کنید، تبدیل را خودتان می‌نویسید:

```go
count := 3
price := 2.5
fmt.Println(float64(count) * price)  // 7.5
fmt.Println(count * price)
```

خط اول اول `count` را به `float64` تبدیل می‌کند و بعد ضرب می‌کند و ۷٫۵ چاپ می‌شود. خط دوم کامپایل نمی‌شود. خطای دقیقی که `go run` داد این است:

```text
./main.go:9:14: invalid operation: count * price (mismatched types int and float64)
```

پیام روشن است: «دو نوع نامنطبق، `int` و `float64`». اول سخت‌گیرانه به نظر می‌رسد، ولی جلوی باگ‌های بی‌صدای دقت عددی را می‌گیرد، چون هر جا نوع عوض می‌شود، در کد دیده می‌شود.

همین قاعده برای نوع‌هایی که خودتان تعریف می‌کنید هم هست. اگر `Celsius` و `Fahrenheit` را هر دو بر پایه‌ی `float64` تعریف کنید، جمع‌کردنشان هم خطای کامپایل می‌دهد (خطای واقعی: `invalid operation: c + f (mismatched types Celsius and Fahrenheit)`). این دقیقاً همان چیزی است که می‌خواهید: نمی‌گذارد درجه‌ی سانتی‌گراد را اشتباهی با فارنهایت جمع کنید.

## if و for و switch

بعد از تعریف داده، نوبت تصمیم و تکرار است. شروع کنیم با `if`. یک چیز در Go فرق دارد: `if` می‌تواند قبل از شرط یک دستور کوچک اجرا کند (**init statement**) و متغیری که آن‌جا می‌سازید فقط داخل همان زنجیره‌ی `if`/`else` زندگی می‌کند:

```go
if n, err := strconv.Atoi("42x"); err != nil {
    fmt.Println("error:", err)
} else {
    fmt.Println(n)
}
// error: strconv.Atoi: parsing "42x": invalid syntax
```

`strconv.Atoi` رشته را به عدد تبدیل می‌کند و دو چیز برمی‌گرداند: خود عدد و یک `err`. اگر تبدیل شکست بخورد، `err` پر است و `nil` نیست. (برگرداندن چند مقدار و `error` را در مقاله‌ی بعد توضیح می‌دهم.) چون `"42x"` عدد معتبری نیست، شاخه‌ی `err != nil` اجرا می‌شود و پیام خطا چاپ می‌شود. نکته‌ی کار این است که `n` و `err` بعد از `if` وجود ندارند و محیط شما را شلوغ نمی‌کنند.

حالا حلقه‌ها. `for` تنها حلقه‌ی Go است، ولی چند شکل دارد:

```go
for i := 0; i < 3; i++ { }          // کلاسیک
for n < 3 { n++ }                    // مثل while
for { if done { break } }            // بی‌نهایت
for i, v := range []string{"a", "b"} { }  // range
for i := range 3 { }                 // 0 1 2 (از Go 1.22)
```

شکل اول همان `for` سه‌قسمتی است که از زبان‌های دیگر می‌شناسید. اگر فقط شرط بنویسید، `for` همان کار `while` را می‌کند. بدون هیچ‌چیز، حلقه‌ی بی‌نهایت است که با `break` تمام می‌شود. `range` روی slice، اندیس و مقدار هر عنصر را می‌دهد، و `range` روی یک عدد از Go 1.22 به بعد از صفر تا یکی مانده به آن می‌شمارد.

`switch` در Go به case بعدی نمی‌افتد. فقط case منطبق اجرا می‌شود و `break` لازم نیست. اگر واقعاً می‌خواهید اجرا به case بعد ادامه پیدا کند، باید صریحاً `fallthrough` بنویسید. هر case می‌تواند چند مقدار داشته باشد، مثل `case 1, 2:`. به‌جای زنجیره‌ی بلند `if/else if` می‌توانید `switch` بدون عبارت بنویسید (معادل `switch true`) که هر case در آن یک شرط است؛ نمونه‌اش را در بخش بعد می‌بینیم.

`break` و `continue` مثل همیشه کار می‌کنند. برای حلقه‌های تو در تو، جلوی حلقه‌ی بیرونی یک **label** (برچسب) می‌گذارید و با نامش به آن اشاره می‌کنید: `continue outer` یا `break outer`.

## کنار هم گذاشتن

حالا چند چیز را با هم به کار می‌بریم: یک جدول تبدیل دما که حلقه، تبدیل نوع و `switch` بدون عبارت دارد. هر دما را از سانتی‌گراد به فارنهایت تبدیل می‌کند و یک برچسب کنارش می‌گذارد:

```go
for c := -10; c <= 40; c += 10 {
    f := float64(c)*9/5 + 32

    var label string
    switch {
    case c < 0:
        label = "freezing"
    case c < 20:
        label = "cool"
    case c < 30:
        label = "warm"
    default:
        label = "hot"
    }
    fmt.Printf("%4d C = %6.1f F  %s\n", c, f, label)
}
```

```text
 -10 C =   14.0 F  freezing
   0 C =   32.0 F  cool
  10 C =   50.0 F  cool
  20 C =   68.0 F  warm
  30 C =   86.0 F  hot
  40 C =  104.0 F  hot
```

حلقه از ۱۰- شروع می‌کند و هر بار ۱۰ درجه جلو می‌رود تا به ۴۰ برسد. برای فرمول فارنهایت، `c` را اول به `float64` تبدیل کرده‌ایم، همان قاعده‌ی «تبدیل ضمنی نداریم». `switch` بدون عبارت از بالا به پایین شرط‌ها را امتحان می‌کند و اولین شرط درست را اجرا می‌کند؛ به همین دلیل برای ۱۰ برچسب `cool` می‌آید (شرط `c < 0` نادرست و `c < 20` درست است). در `Printf`، `%4d` یعنی عدد صحیح در عرض ۴ کاراکتر و `%6.1f` یعنی عدد اعشاری در عرض ۶ با یک رقم اعشار؛ برای همین ستون‌ها زیر هم می‌آیند.

## دام‌های رایج

- **`:=` داخل بلوک داخلی یک متغیر جدید می‌سازد** و متغیر بیرونی را می‌پوشاند (به انگلیسی می‌گویند shadow). مثلاً اگر بیرون از `if` متغیری به اسم `total` باشد و داخل `if` دوباره `total := 99` بنویسید، داخل `if` عدد ۹۹ را می‌بینید ولی بیرون از آن هنوز مقدار قبلی (۱۰) است. این منبع کلاسیک باگ‌هایی است که با «چرا مقدارم عوض نشد» شروع می‌شوند. من این مثال را جدا اجرا کردم و خروجی‌اش `inside: 99` و `outside: 10` بود.
- **از map برابر `nil` می‌شود خواند، ولی نوشتن در آن panic می‌دهد.** خواندن یک کلید از map بدون مقدار `0` برمی‌گرداند، اما نوشتن در آن با پیام `assignment to entry in nil map` برنامه را متوقف می‌کند. اول با `make(map[string]int)` بسازیدش.
- **`len(s)` روی رشته بایت می‌شمارد، نه نویسه.** برای متن غیر انگلیسی از `[]rune` یا `range` کمک بگیرید.
- **متغیر و import استفاده‌نشده خطای کامپایل هستند.** اگر موقع آزمایش متغیری را موقتاً استفاده نمی‌کنید، باید حذفش کنید یا از آن استفاده کنید.
- **`fallthrough` بدون بررسی شرطِ case بعدی به آن می‌پرد.** یعنی بعد از `fallthrough`، بدنه‌ی case بعدی اجرا می‌شود، حتی اگر شرط آن برقرار نباشد.

## تمرین

۱. برنامه‌ای بنویسید که ۱ تا ۳۰ را چاپ کند، اما برای مضرب ۳ «Fizz»، برای مضرب ۵ «Buzz» و برای هر دو «FizzBuzz» بنویسد. از `switch` بدون عبارت استفاده کنید.
۲. دو نوع جدا به نام‌های `Celsius` و `Fahrenheit` بر پایه‌ی `float64` تعریف کنید و سعی کنید آن‌ها را با هم جمع کنید. خطای کامپایلر را بخوانید.
۳. نوع `Level` را با ثابت‌های `iota` به نام‌های `Debug` و `Info` و `Warn` تعریف کنید و هر کدام را چاپ کنید.

## قدم بعدی

توابع، `defer` و مدیریت خطا: در این مقاله دیدیم `strconv.Atoi` عدد و `err` را با هم برمی‌گرداند. آن مقاله نشان می‌دهد این الگو، یعنی برگرداندن error به‌جای exception، چطور کل سبک Go را می‌سازد.
