این تابع چه چاپ می‌کند؟

```python
def add_item(x, bucket=[]):
    bucket.append(x)
    return bucket

print(add_item(1), add_item(2), add_item(3))
```

شاید انتظار داشته باشید `[1] [2] [3]` ببینید، چون هر فراخوانی با یک `bucket` خالی شروع می‌شود. ولی خروجی `[1, 2, 3] [1, 2, 3] [1, 2, 3]` است. این باگ کوچک دری خوب است برای فهمیدن نگاه Python به تابع‌ها. تابع‌ها اعلان ویژه‌ای نیستند که کامپایلر یک بار برپایشان کند. شیء معمولی‌اند و وقتی خط `def` اجرا می‌شود ساخته می‌شوند، و بقیه‌چیز (مقدار پیش‌فرض‌ها، متغیرهایی که تابع به یاد می‌آورد، حتی توقف وسط بدنه‌اش) از همین‌جا می‌آید.

در این پست چهار چیز را مرور می‌کنم که از همین ایده درمی‌آیند: پارامترها، closureها (تابع‌هایی که به یاد می‌آورند)، decoratorها (تابع‌هایی که تابع دیگری را می‌پوشانند) و generatorها (تابع‌هایی که می‌توانند وسط کار بایستند). این پست بر [نوع‌ها و کنترل جریان](/fa/posts/py-types-control-flow/) بنا شده، به‌ویژه بر این ایده که نام برچسبی روی یک شیء است. مقایسه با [توابع در Go](/fa/posts/go-functions-defer-errors/) را فقط جایی آورده‌ام که مطمئنم، و [event loop در Node.js](/fa/posts/node-event-loop/) پیش‌زمینه‌ی خوبی برای بخش closure است.

> همه‌چیز با Python 3.14.0 روی macOS اجرا شده است. فایل‌های دمو اسکریپت‌های محلی `params.py`، `closures.py` و `gens.py` هستند، به‌علاوه‌ی یک برنامه‌ی کوچک Go برای مقایسه‌ی آخر.

## پارامترها

پارامترهای Python گزینه‌های بیشتری از Go دارند. در این امضا، `/` پارامترهای positional-only را تمام می‌کند و `*` پارامترهای keyword-only را شروع می‌کند:

```python
def f(a, b, /, c, *, d=0):
    return (a, b, c, d)
```

قبل از `/` فراخواننده باید آرگومان‌ها را با موقعیت بدهد. بعد از `*` باید با نام بدهد. بین این دو (`c`) هر دو راه جواب می‌دهد. سه فراخوانی و نتیجه‌شان:

```text
f(1, 2, 3, d=4)  -> (1, 2, 3, 4)
f(a=1, b=2, c=3) -> TypeError: f() got some positional-only arguments passed as keyword arguments: 'a, b'
f(1, 2, 3, 4)    -> TypeError: f() takes 3 positional arguments but 4 were given
```

فراخوانی اول درست است. دومی می‌خواهد `a` و `b` را با نام بدهد که `/` ممنوع کرده. سومی `d` را با موقعیت داده که `*` ممنوع کرده، برای همین Python چهار آرگومان موقعیتی می‌شمارد در حالی که فقط سه‌تا مجاز است. پارامترهای keyword-only برای flagها به کار می‌آیند: `f(1, 2, 3, d=4)` در محل فراخوانی خوانا است، ولی یک `4` تنها نه.

حالا برگردیم به معمای اول پست. جواب این است که **مقدار پیش‌فرض یک بار و هنگام اجرای `def` محاسبه می‌شود**، نه در هر فراخوانی. لیست خالی `[]` یک بار ساخته و داخل شیء تابع ذخیره می‌شود. هر فراخوانی‌ای که `bucket` ندهد همان لیست را می‌گیرد. هر سه فراخوانی بالا به همان لیست اضافه کردند. (چاپ بعد از تمام شدن هر سه فراخوانی انجام می‌شود، برای همین حالت نهایی را سه بار می‌بینید.)

راه‌حل این است که پیش‌فرض را `None` بگذارید و لیست را داخل تابع بسازید:

```python
def add_item_fixed(x, bucket=None):
    if bucket is None:
        bucket = []
    bucket.append(x)
    return bucket

print(add_item_fixed(1), add_item_fixed(2))
```

```text
[1] [2]
```

حالا هر فراخوانی‌ای که لیست نگیرد، لیست خودش را می‌سازد. همین دام برای هر پیش‌فرض تغییرپذیر دیگر هم هست، مثل `{}` یا `set()`.

دو شکل دیگر پارامتر. `*args` آرگومان‌های موقعیتی اضافه را در یک tuple جمع می‌کند و `**kwargs` آرگومان‌های نام‌دار اضافه را در یک dict. `*` و `**` سمت فراخوانی هم کار می‌کنند، برای باز کردن یک لیست یا dict به آرگومان:

```python
def show(*args, **kwargs):
    print(args, kwargs)

show(1, 2, x=3)
show(*[1, 2], **{"y": 4})
```

```text
(1, 2) {'x': 3}
(1, 2) {'y': 4}
```

## Closure

چون تابع‌ها مقدارند، می‌توانید یکی را از دیگری برگردانید. و تابع داخلی به متغیرهای تابعی که در آن تعریف شده دسترسی خود را نگه می‌دارد، حتی بعد از اینکه تابع بیرونی تمام شده باشد. این یک {{< term "closure" "closure" >}} است. شمارنده کوچک‌ترین مثال مفید است:

```python
def make_counter():
    count = 0
    def inc():
        nonlocal count
        count += 1
        return count
    return inc

c1, c2 = make_counter(), make_counter()
print(c1(), c1(), c2())
```

```text
1 2 1
```

هر فراخوانی `make_counter()` `count` مخصوص خودش را می‌سازد و `inc`ی که برمی‌گرداند همان را به یاد دارد. پس `c1` ۱ و ۲ می‌شمارد، و `c2` که متغیر خودش را دارد دوباره از ۱ شروع می‌کند. دو شمارنده مستقل‌اند.

خط `nonlocal` مهم است. داخل `inc`، نوشتن `count += 1` معمولاً `count` را به یک متغیر محلی تازه‌ی `inc` تبدیل می‌کند. `nonlocal` می‌گوید «منظورم `count` تابع بیرونی است»، و اجازه می‌دهد آن را **دوباره مقدار بدهید**. (فقط خواندن آن، یا تغییر دادن لیستی که به آن اشاره می‌کند، `nonlocal` نمی‌خواهد.) بدون آن همین تابع خطا می‌دهد:

```text
UnboundLocalError: cannot access local variable 'n' where it is not associated with a value
```

نسخه‌ی دوم دمو `n += 1` را بدون `nonlocal` داخل تابع داخلی دارد. Python یک انتساب می‌بیند، `n` را محلی حساب می‌کند و می‌فهمد هنوز مقداری ندارد.

دام واقعی closureها {{< term "late-binding" "late binding" >}} است: closure متغیر را هنگام اجرا پیدا می‌کند، نه هنگام ساخته‌شدن. این حلقه را ببینید:

```python
fs = [lambda: i for i in range(3)]
print([f() for f in fs])          # [2, 2, 2]
fs = [lambda i=i: i for i in range(3)]
print([f() for f in fs])          # [0, 1, 2]
```

در خط اول سه تابع کوچک می‌سازیم که هرکدام `i` را برمی‌گردانند. ولی هر سه به یک متغیر `i` نگاه می‌کنند و تا وقتی صدایشان می‌زنیم حلقه تمام شده و `i` برابر ۲ است، پس هر سه ۲ برمی‌گردانند. در خط دوم `i=i` مقدار فعلی را به آرگومان پیش‌فرض تبدیل می‌کند. پیش‌فرض‌ها هنگام ساخته‌شدن تابع محاسبه می‌شوند (همان قاعده‌ای که بالا باگ ساخت، این بار به نفع ما)، پس هر lambda مقدار خودش را نگه می‌دارد. در دمو `functools.partial(lambda i: i, i)` هم `[0, 1, 2]` چاپ کرد.

## Decorator

decorator تابعی است که یک تابع می‌گیرد و جایگزینی برایش برمی‌گرداند. خط `@name` بالای `def` فقط شکل کوتاه نوشتن `hello = name(hello)` است. `@timed` من ساده است: فراخوانی‌ها را می‌شمارد (اسمش را `timed` گذاشته‌ام ولی زمان اندازه نمی‌گیرد):

```python
def timed(fn):
    def wrapper(*a, **k):
        wrapper.calls += 1
        return fn(*a, **k)
    wrapper.calls = 0
    return wrapper
```

`wrapper` هر آرگومانی را می‌پذیرد، شمارنده‌ای را که روی خود تابع نگه داشته (تابع‌ها شیء‌اند، پس می‌توانند attribute داشته باشند) یکی زیاد می‌کند و تابع اصلی را صدا می‌زند. یک هزینه هست: تابع تزیین‌شده حالا در واقع `wrapper` است، پس اسم و docstring خودش را از دست می‌دهد. راه‌حل `functools.wraps(fn)` است. همان تابع را یک بار با `@timed` و یک بار با نسخه‌ای که `@functools.wraps(fn)` دارد اجرا کردم:

```text
wrapper None 2
hello2 say hello 3
```

هر خط `__name__`، `__doc__` و `calls` است. در خط اول تابع می‌گوید اسمش `wrapper` است و docstring ندارد. در دومی `wraps` اسم و docstring اصلی را کپی کرده (`hello2` و `say hello`). شمارش‌ها ۲ و ۳ است چون دو و سه بار صدایشان زدم. دیباگر، لاگ و ابزارهای مستندسازی همه از `__name__` استفاده می‌کنند، پس همیشه از `wraps` استفاده کنید.

decorator با آرگومان یک سطح بیشتر دارد: تابعی که decorator را برمی‌گرداند. این `@retry(times=3)` اگر تابع `ConnectionError` بیندازد دوباره صدایش می‌زند. تابع آزمایشی دو بار اول شکست می‌خورد و بار سوم موفق می‌شود، پس دمو قطعی است:

```text
  attempt 1 failed: boom #1
  attempt 2 failed: boom #2
ok after 3 calls
```

دو شکست گرفته و چاپ شد و فراخوانی سوم عادی برگشت. با `times=2` و تابعی که همیشه شکست می‌خورد، دو تلاش چاپ شد و بعد `gave up: down`: در تلاش آخر exception دوباره پرتاب می‌شود و بلعیده نمی‌شود، تا فراخواننده بفهمد شکست خورده.

## Generator

سؤالی که پشت generator است: اگر تابعی بتواند مقداری بدهد و دفعه‌ی بعد که خواستیم از همان جا ادامه بدهد چه؟ در Python هر تابعی که `yield` داشته باشد همین کار را می‌کند. صدا زدنش بدنه را اجرا نمی‌کند. یک **generator** برمی‌گرداند، شیئی که بدنه را فقط وقتی مقدار بعدی را بخواهید اجرا می‌کند. این دمو با چاپ‌کردن داخل تابع این را دیدنی می‌کند:

```python
def count_to(n):
    print("start")
    for i in range(1, n + 1):
        print("yield", i)
        yield i
    print("end")

g = count_to(2)
print("created, nothing printed yet")
print(next(g))
print(next(g))
try:
    next(g)
except StopIteration:
    print("StopIteration")
```

```text
created, nothing printed yet
start
yield 1
1
yield 2
2
end
StopIteration
```

خط‌به‌خط دنبالش کنیم:

1. `g = count_to(2)` چیزی را اجرا نکرد. اولین چیزی که چاپ شد پیام خودمان است.
2. اولین `next(g)` بدنه را از بالا تا اولین `yield` اجرا می‌کند: `start` و `yield 1` را چاپ می‌کند، بعد می‌ایستد و `1` را تحویل می‌دهد. `print` ما آن را نشان می‌دهد.
3. دومین `next(g)` درست بعد از همان `yield` ادامه می‌دهد. حلقه جلو می‌رود، `yield 2` چاپ می‌شود و `2` تحویل داده می‌شود.
4. سومین `next(g)` دوباره ادامه می‌دهد. حلقه تمام است، `end` چاپ می‌شود، بدنه به پایان می‌رسد و Python برای اینکه بگوید چیزی نمانده `StopIteration` می‌اندازد.

این همان {{< term "lazy-evaluation" "ارزیابی تنبل" >}} است: کار فقط وقتی انجام می‌شود که کسی مقدار بخواهد، و یکی‌یکی. حلقه‌ی `for` این `next`ها را صدا می‌زند و `StopIteration` را خودش می‌گیرد.

برد عملی در حافظه است. این عددها از `sys.getsizeof` آمده‌اند: برای `list(range(1_000_000))` برابر ۸۰۰۰۰۵۶ بایت است و برای generator expression به شکل `(x for x in range(1_000_000))` برابر ۲۰۰ بایت. لیست یک میلیون ورودی نگه می‌دارد. generator شیء کوچکی است که آن‌ها را در صورت نیاز تولید می‌کند (پس ۲۰۰ بایت اندازه‌ی خود generator است، نه مقدارهایی که بعداً می‌دهد؛ و عدد لیست اندازه‌ی حافظه‌ی خود لیست است، بدون شمردن خود شیءهای عدد صحیح). هزینه‌اش این است که generator یک‌بارمصرف است. در دمو اولین `sum` روی generator برابر `499999500000` شد و دومی `0`، چون generator قبلاً تمام شده بود.

generator می‌تواند با `yield from` کار را به generator دیگر بسپارد و با `send()` مقدار هم بگیرد. هر دو در یک دمو:

```python
def inner():
    yield 1
    yield 2
def outer():
    yield 0
    yield from inner()
    yield 3
print(list(outer()))

def acc():
    total = 0
    while True:
        x = yield total
        total += x
a = acc(); next(a)
print(a.send(5), a.send(10))
```

```text
[0, 1, 2, 3]
5 15
```

`outer` اول ۰ می‌دهد، بعد کار را به `inner` می‌سپارد (که ۱ و ۲ می‌دهد)، و بعد ۳. در `acc`، `yield total` هم مجموع جاری را می‌دهد و هم مقداری را که با `send()` فرستاده می‌شود می‌گیرد. اولین `next(a)` فقط تا اولین `yield` جلو می‌رود؛ بعد از آن `send(5)` مجموع را ۵ می‌کند و `send(10)` آن را ۱۵. درباره‌ی `send()` همین‌قدر کافی است: کم لازم می‌شود.

## پروتکل iterator

`for` از کجا می‌داند با یک generator، یک لیست یا یک فایل چه کند؟ از یک قرارداد کوچک به اسم پروتکل {{< term "iterator" "iterator" >}}. `for` روی شیء `iter()` صدا می‌زند تا یک iterator بگیرد، و بعد `__next__()` را مکرر صدا می‌زند تا `StopIteration` بیاید. می‌توانید یکی را دستی بنویسید:

```python
class Countdown:
    def __init__(self, n): self.n = n
    def __iter__(self): return self
    def __next__(self):
        if self.n <= 0:
            raise StopIteration
        self.n -= 1
        return self.n + 1
```

```text
[3, 2, 1]
2 1
exhausted
```

خط اول `list(Countdown(3))` است. دو خط بعد از صدا زدن دستی `next` روی `iter(Countdown(2))` آمده: ۲ و بعد ۱ می‌دهد و فراخوانی سوم `StopIteration` می‌اندازد (دمو `exhausted` چاپ می‌کند). generator فقط شکل کوتاه نوشتن همین است: Python خودش `__iter__` و `__next__` را می‌سازد.

## itertools و lru_cache

کتاب‌خانه‌ی استاندارد ابزارهای آماده برای iteratorها دارد. دو مورد از دمو:

```text
list(islice(naturals(), 5))      [0, 1, 2, 3, 4]
list(chain([1, 2], "ab", (9,)))  [1, 2, 'a', 'b', 9]
```

`naturals()` یک generator بی‌پایان است (`0, 1, 2, ...`). چون تنبل است، `islice` می‌تواند فقط پنج‌تای اول را بردارد و بایستد. `chain` چند iterable را به یک جریان وصل می‌کند.

`groupby` یک دام دارد: فقط عنصرهای **مجاور** را گروه می‌کند. روی `["apple", "avocado", "banana", "blueberry", "apricot"]` و گروه‌بندی با حرف اول، دمو این را چاپ کرد:

```text
[('a', ['apple', 'avocado']), ('b', ['banana', 'blueberry']), ('a', ['apricot'])]
[('a', ['apple', 'apricot', 'avocado']), ('b', ['banana', 'blueberry'])]
```

خط اول لیست مرتب‌نشده است: سه گروه، که `a` دو بار آمده، چون `apricot` کنار بقیه‌ی کلمه‌های `a` نیست. خط دوم لیست مرتب‌شده است: دو گروه. اگر برای هر کلید یک گروه می‌خواهید، اول مرتب کنید.

{{< term "memoization" "Memoization" >}} یعنی به یاد سپردن نتیجه‌ی تابع برای ورودی‌هایی که قبلاً دیده. در Python یک خط است: `@functools.lru_cache`. برای فیبوناچی بازگشتی، که وگرنه همان فراخوانی‌ها را بارها تکرار می‌کند، `fib(30)` برابر `832040` برگشت و `cache_info()` این را چاپ کرد:

```text
CacheInfo(hits=28, misses=31, maxsize=None, currsize=31)
```

۳۱ ورودی متفاوت داریم (۰ تا ۳۰) که هرکدام یک بار محاسبه شد (۳۱ miss)، و بقیه‌ی فراخوانی‌ها (۲۸ hit) از cache جواب گرفتند.

## مقایسه با Go

Go هم closure دارد و آن‌ها هم مثل Python متغیر را می‌گیرند، نه مقدار را. (Go 1.22 حلقه‌ی `for` را عوض کرد تا هر دور متغیر تازه داشته باشد؛ رفتار متغیر حلقه در Go را اینجا آزمایش نکردم.) Go کلیدواژه‌ی `yield` ندارد. از Go 1.23 iteratorهای range-over-function را دارد، و من با Go 1.27.3 برنامه‌ی کوچکی با `iter.Seq[int]` (تابعی که یک callback به شکل `yield func(int) bool` می‌گیرد) اجرا کردم؛ `for v := range Count(3)` اعداد ۱، ۲ و ۳ را، هرکدام در یک خط، چاپ کرد. این مدل push است: تابع iterator بدنه‌ی حلقه‌ی شما را صدا می‌زند. generator در Python مدل pull است: شما `next()` صدا می‌زنید و generator یک مقدار تحویل می‌دهد.

## اشتباه‌های رایج با تابع و generator

- **آرگومان پیش‌فرض تغییرپذیر.** `bucket=[]` یک بار ساخته می‌شود و بین همه‌ی فراخوانی‌ها مشترک است. `None` بگذارید و لیست را داخل تابع بسازید.
- **انتظار اینکه closure مقدار را بگیرد.** closure متغیر را می‌گیرد و موقع صدا شدن پیدا می‌کند. در حلقه از `i=i` (یا `functools.partial`) استفاده کنید تا مقدار فعلی ثابت شود.
- **decorator بدون `functools.wraps`.** تابع پوشانده‌شده اسم و docstring خودش را از دست می‌دهد و لاگ و traceback گیج‌کننده می‌شود.
- **`groupby` روی داده‌ی مرتب‌نشده.** فقط همسایه‌ها را گروه می‌کند، پس اول با همان کلید مرتب کنید.
- **استفاده‌ی دوباره از generator.** فقط یک بار مصرف می‌شود؛ دور دوم چیزی نمی‌بیند (`sum` دوم بالا ۰ داد).
- **آرگومان hash‌ناپذیر برای `lru_cache`.** cache آرگومان‌ها را به‌عنوان کلید dict به کار می‌برد، پس لیست و dict به‌عنوان آرگومان خطا می‌دهند.

## تمرین

1. `@count_calls` را بنویسید که `.calls` را در دسترس بگذارد، بعد `@retry` را روی آن اضافه کنید.
2. یک generator به اسم `chunks(iterable, n)` با `islice` بنویسید.
3. دام `groupby` را بازتولید کنید و به دو روش درستش کنید.
