سه خط Python را ببینید:

```python
a = [1, 2, 3]
b = a
b.append(4)
```

حالا `a` را چاپ کنید: `[1, 2, 3, 4]` است. من فقط به `b` دست زدم، ولی `a` هم عوض شد. در خیلی از زبان‌ها انتساب یعنی «این مقدار را بگذار در آن جعبه»، و این نتیجه شبیه یک باگ به نظر می‌رسد. در Python این همان قاعده‌ی عادی است، و برای کسی که مثل من از Go آمده، بزرگ‌ترین تغییر در پایه‌های زبان است.

ایده این است: در Python **نوع مال مقدار است، نه مال متغیر**. متغیر فقط یک نام است، یک برچسب که روی یک شیء می‌چسبانید. `b = a` چیزی را کپی نمی‌کند؛ فقط برچسب دومی روی همان شیء می‌چسباند. چند چیز در این نوشته از همین یک جمله می‌آید: چرا نوع اعلام نمی‌کنیم، چرا کپی‌کردن یک لیست مراقبت می‌خواهد، و چرا `is` و `==` دو سؤال متفاوت‌اند.

[پست قبل](/fa/posts/py-environment-uv-venv/) یک محیط کاری آماده کرد، پس حالا می‌توانیم کد بنویسیم. به ترتیب سراغ نوع‌ها، نام‌ها و کنترل جریان می‌روم. مقایسه با [نوع‌ها و کنترل جریان در Go](/fa/posts/go-types-control-flow/) را فقط جایی آورده‌ام که از درستی‌اش مطمئنم.

> همه‌ی مثال‌ها با Python 3.14.0 روی macOS اجرا شده‌اند (`python3 --version` همین را چاپ می‌کند). فایل‌های دمو اسکریپت‌های محلی `basics.py`، `flow.py` و `ident.py` و سه فایل کوچک با خطای syntax عمدی هستند. برای خطاهای syntax فقط خط آخر خروجی را آورده‌ام.

## پویا، اما قوی

در Go می‌نویسید `var x int` و `x` هیچ‌وقت رشته نگه نمی‌دارد. در Python چیزی اعلام نمی‌کنید. یک نام می‌تواند الان به یک `int` اشاره کند و لحظه‌ای بعد به یک `str`:

```python
x = 5
print(type(x).__name__, x)
x = 'five'
print(type(x).__name__, x)
```

```text
int 5
str five
```

به این می‌گویند **تایپ پویا** (dynamic typing): نوع‌ها موقع اجرای برنامه بررسی می‌شوند، نه قبل از آن. این به معنی بی‌توجهی Python به نوع نیست. مقدار `5` همیشه یک `int` است و Python بی‌صدا آن را به رشته تبدیل نمی‌کند (به این «تایپ قوی» می‌گویند و تفاوت Python با JavaScript همین‌جاست):

```python
try:
    1 + '1'
except TypeError as e:
    print("TypeError:", e)
```

```text
TypeError: unsupported operand type(s) for +: 'int' and 'str'
```

این خطا فقط وقتی دیده می‌شود که همین خط واقعاً اجرا شود. در Go همین اشتباه خطای کامپایل است و برنامه اصلاً شروع نمی‌شود. هزینه‌ی واقعی تایپ پویا همین است: اشتباه روی خطی که کم اجرا می‌شود تا وقتی کسی آن را اجرا نکند پنهان می‌ماند. در ادامه‌ی سری می‌بینیم type hint و یک checker چطور بخشی از این امنیت را برمی‌گردانند.

## عددها

سه نوع عدد در کار روزمره پیش می‌آید: `int`، `float` و، وقتی دقت دقیق می‌خواهید، `decimal.Decimal` و `fractions.Fraction`. دمو چند مقدار چاپ می‌کند:

```python
from decimal import Decimal
from fractions import Fraction

print(2**200)
print(0.1 + 0.2, 0.1 + 0.2 == 0.3)
print(Decimal('0.1') + Decimal('0.2'), Fraction(1, 10) + Fraction(2, 10))
```

```text
1606938044258990275541962092341162602522202993782792835301376
0.30000000000000004 False
0.3 3/10
```

خط‌به‌خط بخوانیم:

- **خط اول:** `int` عدد صحیح با {{< term "arbitrary-precision" "دقت دلخواه" >}} است. هر قدر لازم باشد بزرگ می‌شود، پس `2**200` بی‌مشکل کار می‌کند و سرریز نمی‌کند. `int` در Go اما عرض ثابت دارد.
- **خط دوم:** `float` همان ممیز شناور دودویی معمول است، مثل `float64` در Go یا `number` در JavaScript. کامپیوتر نمی‌تواند `0.1` را در دودویی دقیق نگه دارد، پس جمع کمی اشتباه است و مقایسه با `0.3` برابر `False` درمی‌آید.
- **خط سوم:** `Decimal` حساب ده‌دهی می‌کند، پس `0.1 + 0.2` دقیقاً `0.3` است. `Fraction` یک کسر دقیق نگه می‌دارد و `3/10` چاپ می‌کند. (`print` شکل خوانا را نشان می‌دهد؛ شکل `repr` آن `Decimal('0.3')` می‌شود.)

برای پول از `Decimal` استفاده کنید و آن را از **رشته** مثل `'0.1'` بسازید. اگر `Decimal(0.1)` بنویسید، یک float را که از قبل نادقیق است به آن داده‌اید.

## رشته و bytes

`str` دنباله‌ی تغییرناپذیر از کاراکترهای Unicode است. `bytes` نوع جداگانه‌ای است: عددهای خام بین ۰ تا ۲۵۵. این دو هیچ‌وقت برابر نمی‌شوند، حتی اگر شبیه هم به نظر برسند:

```python
s = 'سلام'
print(len(s), len(s.encode()), s.encode())
print(s[1:3], s[::-1])
try:
    s[0] = 'x'
except TypeError as e:
    print("TypeError:", e)
print(b'abc'[0], 'abc'.encode() == b'abc', 'abc' == b'abc')
```

```text
4 8 b'\xd8\xb3\xd9\x84\xd8\xa7\xd9\x85'
لا مالس
TypeError: 'str' object does not support item assignment
97 True False
```

- **خط ۱:** کلمه ۴ کاراکتر دارد، ولی `s.encode()` آن را به بایت‌های UTF-8 تبدیل می‌کند و ۸ بایت درمی‌آید (هر کدام از این حرف‌های فارسی دو بایت می‌گیرد). `len` روی `str` کاراکتر می‌شمارد و روی `bytes` بایت.
- **خط ۲:** برش و برعکس‌کردن روی کاراکترها کار می‌کند. `s[1:3]` حرف دوم و سوم است و `s[::-1]` هر چهار حرف به ترتیب معکوس (ترمینالی که متن راست‌به‌چپ نشان می‌دهد ممکن است این را عجیب نشان دهد). برخلاف `string` در Go که با بایت اندیس می‌خورد، اندیس‌زدن روی `str` در Python کاراکتر کامل می‌دهد.
- **خط ۳:** رشته تغییرناپذیر است. نمی‌توانید به `s[0]` مقدار بدهید؛ به‌جایش رشته‌ی جدید می‌سازید.
- **خط ۴:** اندیس‌زدن روی `bytes` یک عدد می‌دهد (`97` همان `a` است). رشته‌ی encode‌شده با literal از نوع bytes برابر است، ولی خود `str` نه، چون دو نوع متفاوت‌اند.

با f-string می‌توانید مقدارها را داخل رشته قالب‌بندی کنید. بعد از دو نقطه می‌شود مشخصات قالب را داد:

```python
name, price = 'Roham', 1234.5678
print(f'{name:>8}|{price:,.2f}|{42:05d}|{255:#x}|{0.256:.1%}')
```

```text
   Roham|1,234.57|00042|0xff|25.6%
```

به ترتیب: تراز راست در ۸ کاراکتر، جداکننده‌ی هزارگان با دو رقم اعشار، صفر پشت عدد تا ۵ رقم، مبنای ۱۶ با پیشوند `0x`، و درصد با یک رقم اعشار.

## Truthiness و None

در `if` یا `while` لازم نیست حتماً یک `bool` داشته باشید. هر شیء یک {{< term "truthiness" "truthiness" >}} دارد: وقتی به‌عنوان شرط به کار می‌رود، درست یا نادرست حساب می‌شود. دمو `bool()` را روی چند مقدار اجرا می‌کند:

```text
     0 -> False
    '' -> False
    [] -> False
    {} -> False
  None -> False
   0.0 -> False
   'a' -> True
   [0] -> True
   0.1 -> True
```

قاعده‌ی سرانگشتی «خالی یا صفر یعنی نادرست» است. عدد صفر، رشته‌ی خالی، containerهای خالی و `None` نادرست‌اند و بقیه درست. `[0]` درست است چون لیست یک عضو دارد، حتی اگر آن عضو صفر باشد. (طبق مستندات، کلاس‌های خودتان درست حساب می‌شوند مگر `__bool__` یا `__len__` تعریف کنند.) به همین دلیل در کد Python به‌جای `if len(items) > 0:` می‌نویسند `if items:`.

`None` یعنی «بدون مقدار» در Python، شبیه `nil` در Go یا `null` در JavaScript. برای بررسی‌اش از `is` استفاده کنید، نه `==`:

```python
x = None
print(x is None, x == None)
```

```text
True True
```

اینجا هر دو `True` است، ولی `x is None` می‌پرسد «آیا این دقیقاً همان شیء است؟» و کلاسی که `__eq__` خودش را دارد نمی‌تواند آن را فریب بدهد. این ما را به موضوع اصلی این پست می‌رساند.

## نام‌ها ارجاع‌اند

برگردیم به مثال اول. نام یک برچسب روی شیء است، نه جعبه‌ای که مقدار را نگه می‌دارد. دو برچسب می‌توانند به یک شیء اشاره کنند:

```python
a = [1, 2, 3]
b = a
b.append(4)
print(a, a is b, id(a) == id(b))
```

```text
[1, 2, 3, 4] True True
```

`append` همان یک لیستی را عوض کرد که هر دو نام به آن اشاره می‌کنند. `a is b` می‌پرسد «آیا این‌ها یک شیء‌اند؟» و `id()` هویت شیء را برمی‌گرداند؛ هر دو می‌گویند بله. (عددی که `id` برمی‌گرداند در هر اجرا فرق می‌کند، برای همین فقط آن‌ها را با هم مقایسه کردم.)

اگر لیست مستقل می‌خواهید باید آن را کپی کنید، ولی کپی چند سطح دارد. لیستی را در نظر بگیرید که داخلش لیست است:

```python
import copy
nested = [[1], [2]]
sh = nested.copy()          # shallow
dp = copy.deepcopy(nested)  # deep
nested[0].append(99)
print(sh, dp)
```

```text
[[1, 99], [2]] [[1], [2]]
```

{{< term "shallow-copy" "کپی سطحی" >}} یک لیست بیرونی جدید می‌سازد، ولی لیست‌های داخلی همان شیءهای قبلی‌اند. پس وقتی لیست داخلی را از طریق `nested` عوض کردیم، `sh` هم تغییر را دید. `copy.deepcopy` همه‌چیز را تا ته کپی می‌کند، برای همین `dp` دست‌نخورده ماند.

یک غافلگیری دیگر درباره‌ی هویت هست، از `ident.py`:

```python
a = int('1000'); b = int('1000')
print(a is b, a == b)
c = int('100'); d = int('100')
print(c is d, c == d)
```

```text
False True
True True
```

هر دو جفت برابرند، ولی فقط عددهای کوچک یک شیء‌اند. این جزئیات پیاده‌سازی CPython است (طبق مستندات، برای عدد صحیح‌های منفی ۵ تا ۲۵۶ شیءهای آماده نگه می‌دارد). حتی داخل یک فایل هم ممکن است فرق کند: در `basics.py`، `n = 1000; m = 1000; n is m` مقدار `True` چاپ کرد، چون کامپایلر برای دو عدد یکسان در همان فایل یک شیء ثابت به کار برده. درس این نیست که این حالت‌ها را حفظ کنید؛ درس این است که `is` را روی عددها به کار نبرید: `==` مقدار را مقایسه می‌کند، `is` هویت را، و `is` را تقریباً فقط برای `None` می‌خواهید.

## کنترل جریان

Python بلوک‌ها را با تورفتگی (indentation) مشخص می‌کند، نه آکولاد، و سرِ هر بلوک یک دو نقطه می‌آید. این سه اشتباهی است که مبتدی‌ها اول از همه می‌زنند. هرکدام در زمان parse متوقف می‌شود، یعنی قبل از اجرای هر خطی:

```text
IndentationError: expected an indented block after 'if' statement on line 1
SyntaxError: expected ':'
IndentationError: unindent does not match any outer indentation level
```

این‌ها از سه فایل کوچک آمده‌اند: بلوکی بدون تورفتگی، `if x > 2` بدون دو نقطه، و خطی که به ترازی برگشته که با هیچ بلوک بیرونی نمی‌خواند.

شرط و حلقه این شکل را دارند. `for` روی هر iterable می‌گردد، پس لازم نیست شمارنده را دستی بنویسید:

```python
age = 20
label = 'adult' if age >= 18 else 'minor'
for i in range(10, 0, -3): print(i, end=' ')      # 10 7 4 1
for name, score in zip(['a', 'b', 'c'], [90, 80]):
    print(name, score)                              # a 90, b 80
```

خط دوم عبارت شرطی است (Python عملگر `?:` ندارد). `range(10, 0, -3)` از ۱۰ شروع می‌کند، سه‌تا سه‌تا پایین می‌آید و قبل از ۰ می‌ایستد. `zip` دو لیست را کنار هم می‌پیماید و با کوتاه‌ترین متوقف می‌شود، پس `c` حذف می‌شود. `enumerate` اندیس و مقدار را با هم می‌دهد؛ همین را در مثال بعد می‌بینیم.

حلقه‌های Python یک ویژگی عجیب دارند: `else` ای که فقط وقتی اجرا می‌شود که حلقه بدون `break` تمام شده باشد. برای جست‌وجو ساخته شده:

```python
def find(items, target):
    for i, v in enumerate(items):
        if v == target:
            print('found at', i)
            break
    else:
        print('not found')

find([3, 5, 7], 5)
find([3, 5, 7], 9)
```

```text
found at 1
not found
```

در فراخوانی اول `break` اجرا می‌شود و `else` رد می‌شود. در دومی حلقه بدون `break` به آخر می‌رسد و `else` اجرا می‌شود. این‌طور بخوانید: «else یعنی break نشد».

دو ابزار کوچک مانده است. {{< term "walrus-operator" "عملگر walrus" >}} یعنی `:=` داخل یک عبارت مقدار می‌دهد، و {{< term "list-comprehension" "list comprehension" >}} یک لیست را در یک خط می‌سازد. درباره‌ی comprehension همین‌قدر می‌گویم:

```python
data = [1, 2, 3, 4, 5, 6]
if (k := len(data)) > 5:
    print('long list of', k)
print([x * x for x in data if x % 2 == 0])
```

```text
long list of 6
[4, 16, 36]
```

walrus هنگام آزمایش‌کردن `len(data)` آن را در `k` ذخیره کرد، تا خط بعد بتوانیم از `k` استفاده کنیم. comprehension این‌طور خوانده می‌شود: «`x * x` برای هر `x` در `data`، ولی فقط وقتی `x` زوج است».

## match

Python 3.10 دستور `match` را اضافه کرد. {{< term "structural-pattern-matching" "Structural pattern matching" >}} شبیه `switch` است، ولی مقدار را بر اساس شکلش هم باز می‌کند: literal، دنباله، mapping و کلاس، همراه با guard اختیاری. تابع زیر هشت نوع مقدار را بررسی می‌کند (یک dataclass به اسم `Point` به کار رفته که دو پست بعد با آن آشنا می‌شویم؛ فعلاً فقط کلاسی با فیلدهای `x` و `y` است):

```python
def describe(v):
    match v:
        case 0:
            return 'zero'
        case int(n) if n < 0:
            return f'negative {n}'
        case [first, *rest]:
            return f'list starting {first}, {len(rest)} more'
        case {'status': 'ok', 'items': items}:
            return f'ok with {len(items)} items'
        case Point(x=0, y=0):
            return 'origin'
        case Point(x=x, y=y):
            return f'point {x},{y}'
        case str() | bytes():
            return 'text'
        case _:
            return 'other'
```

```text
0 -> zero
-5 -> negative -5
[1, 2, 3] -> list starting 1, 2 more
{'status': 'ok', 'items': [1]} -> ok with 1 items
Point(x=0, y=0) -> origin
Point(x=1, y=2) -> point 1,2
'hi' -> text
3.5 -> other
```

caseها از بالا به پایین امتحان می‌شوند و اولین تطبیق برنده است. `int(n) if n < 0` یک `int` را می‌پذیرد و به `n` وصل می‌کند، ولی فقط وقتی guard (`n < 0`) درست باشد؛ برای همین `-5` اینجا می‌افتد. `[first, *rest]` هر دنباله‌ی دست‌کم یک‌عضوی را می‌پذیرد و تکه‌تکه می‌کند. الگوی dict بررسی می‌کند کلیدها با آن مقدارها هستند و `items` را بیرون می‌کشد. `Point(x=0, y=0)` الگوی کلاس است و `Point(x=x, y=y)` بعد از آن هر نقطه‌ی دیگر را می‌گیرد. `case _` آخر پیش‌فرض است. یک نکته: رشته هم دنباله است، ولی Python در الگوهای دنباله‌ای مثل `[first, *rest]` با `str` و `bytes` مثل دنباله رفتار نمی‌کند؛ برای همین `'hi'` به case مربوط به `text` می‌رسد.

## دام‌های رایج

- **اسم‌گذاری اسکریپت مثل ماژول کتاب‌خانه‌ی استاندارد.** من یک بار اسکریپتی را `types.py` نامیدم و همه‌ی importها با `cannot import name 'GenericAlias' from 'types'` خراب شد. Python فایل مرا زودتر از ماژول واقعی پیدا کرد. اسمی انتخاب کنید که کتاب‌خانه‌ی استاندارد ندارد.
- **استفاده از `float` برای پول.** `0.1 + 0.2 != 0.3` باگ Python نیست، طبیعت ممیز شناور دودویی است. از `Decimal` ساخته‌شده از رشته استفاده کنید.
- **استفاده از `is` برای مقدارها.** `is` برای `None` و singletonهای دیگر است. برای بقیه `==` بنویسید، همان‌طور که مثال `1000` نشان داد.
- **فراموش‌کردن اینکه انتساب شیء را به اشتراک می‌گذارد.** وقتی استقلال می‌خواهید صریح کپی کنید، و یادتان باشد `copy()` سطحی است: شیءهای داخلی هنوز مشترک‌اند.
- **اشتباه خواندن `for ... else`.** معنی‌اش «اگر حلقه اجرا نشد» نیست. معنی‌اش «اگر حلقه `break` نشد» است.

## تمرین

1. `len` را برای `'é'` به‌صورت یک کاراکتر و برای `'é'` (یک `e` به‌علاوه‌ی accent ترکیبی) چاپ کنید و نتیجه را توضیح دهید. هر دو را با `==` هم مقایسه کنید.
2. تابع `classify(v)` را با `match` برای int، لیست خالی و dict دارای کلید `"type"` بنویسید.
3. با `for ... else` اولین عدد بخش‌پذیر بر ۷ را در یک لیست پیدا کنید و اگر نبود پیامی چاپ کنید.
