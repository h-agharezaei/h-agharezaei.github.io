فرض کنید تصمیم گرفته‌اید Rust یاد بگیرید و اولین سؤال‌تان این است: چه چیزی نصب کنم و چه چیزی تایپ کنم؟ جواب کوتاه این است که تقریباً هیچ‌وقت خود کامپایلر Rust، یعنی `rustc`، را مستقیم صدا نمی‌زنید. دو ابزار جلوی آن ایستاده‌اند. {{< term "rustup" "rustup" >}} کامپایلر و ابزارهای دور و برش را نصب و به‌روز می‌کند. {{< term "cargo" "Cargo" >}} پروژه می‌سازد، کد را build و اجرا می‌کند، کتاب‌خانه‌ها را اضافه می‌کند و کد را مرتب می‌کند. نقش Cargo تقریباً همان نقش دستور `go` در Go است.

این مقاله شروع یک سری آموزشی Rust هم هست، از مقدماتی تا پیشرفته. بیشتر سال‌های کاری‌ام را با Go و Node.js سرویس backend نوشته‌ام و حالا دارم Rust را علنی یاد می‌گیرم. چند مقاله درباره‌ی Go هم نوشته‌ام (از [شروع کار با Go](/fa/posts/go-getting-started/) شروع می‌شود)، برای همین هرجا مقایسه کمک کند، Rust را با Go مقایسه می‌کنم.

اصلاً چرا Rust؟ نه چون مد شده. Rust امنیت حافظه را بدون {{< term "garbage-collector" "garbage collector" >}} می‌دهد؛ یعنی برنامه‌تان نیازی به یک بخش جداگانه ندارد که حافظه‌ی مصرف‌شده را جمع کند، و با این حال خطاهایی مثل دسترسی به حافظه‌ی آزادشده را کامپایلر می‌گیرد. سرعتش در حد C و C++ است. و سیستم نوع (type system) قوی‌ای دارد که خیلی از باگ‌ها را از زمان اجرا به زمان کامپایل می‌آورد. هزینه‌اش یک منحنی یادگیری تندتر است و کامپایلری که اوایل زیاد با شما بحث می‌کند. این مقاله هنوز سراغ آن بحث‌ها نمی‌رود. فقط درباره‌ی ابزارهاست: نصب کنیم، یک پروژه بسازیم و یک برنامه اجرا کنیم.

> همه‌ی مثال‌ها را با Rust 1.90.0 روی macOS اجرا کرده‌ام. زمان‌های build و عددهای تصادفی در هر اجرا فرق می‌کنند.

## نصب با rustup

راه رسمی نصب Rust، ابزاری به اسم **rustup** است. rustup یک «مدیر toolchain» است. toolchain یعنی مجموعه‌ی ابزارهایی که برای کار با زبان لازم دارید: کامپایلر، Cargo و چند ابزار دیگر. rustup آن‌ها را نصب می‌کند و بعداً هم می‌شود با آن به نسخه‌ی جدیدتر رفت. دستور نصب را از https://rustup.rs می‌گیرید:

```bash
curl --proto '=https' --tlsv1.2 -sSf https://sh.rustup.rs | sh
```

بعد از نصب، با `rustup update` می‌توانید به‌روز کنید. برای اینکه مطمئن شوید همه‌چیز سر جایش است، نسخه‌ی کامپایلر و Cargo را بپرسید:

```bash
$ rustc --version
rustc 1.90.0 (1159e78c4 2025-09-14)
$ cargo --version
cargo 1.90.0 (840b83a10 2025-07-30)
```

دو خط جواب می‌دهند که هر دو ابزار نصب‌اند و هر دو نسخه‌ی 1.90.0 هستند. شماره‌ی نسخه‌ی شما احتمالاً بالاتر است و اشکالی ندارد.

## اولین پروژه با Cargo

حالا یک پروژه‌ی تازه می‌سازیم. دستور `cargo new` یک پوشه با ساختار آماده درست می‌کند:

```bash
$ cargo new rust-getting-started
    Creating binary (application) `rust-getting-started` package
$ cd rust-getting-started
```

`binary (application)` یعنی پروژه‌ای که یک برنامه‌ی اجرایی می‌سازد. (نوع دیگر، کتاب‌خانه است که کد را برای پروژه‌های دیگر فراهم می‌کند.) داخل پوشه دو چیز مهم هست. فایل `src/main.rs` نقطه‌ی شروع برنامه است. فایل `Cargo.toml` هم شناسنامه‌ی پروژه است: اسم، نسخه و فهرست کتاب‌خانه‌هایی که به آن‌ها نیاز دارد. اگر با Go کار کرده‌اید، شبیه `go.mod` است. این `Cargo.toml` است که `cargo new` ساخته:

```toml
[package]
name = "rust-getting-started"
version = "0.1.0"
edition = "2024"

[dependencies]
```

خط `edition` را باید یک بار توضیح داد. زبان‌ها معمولاً برای اینکه جلو بروند باید گاهی چیزی را بشکنند. Rust این کار را با «edition» حل کرده است: هر پروژه می‌گوید با کدام edition زبان نوشته شده و کامپایلر همان را رعایت می‌کند. پس زبان می‌تواند پیشرفت کند، بدون اینکه کدهای قدیمی از کار بیفتند. بخش `[dependencies]` هم فعلاً خالی است.

`cargo new` در `src/main.rs` یک برنامه‌ی hello world هم گذاشته است. دستور `cargo run` اول آن را کامپایل می‌کند و بعد اجرایش می‌کند:

```bash
$ cargo run
   Compiling rust-getting-started v0.1.0 (...)
    Finished `dev` profile [unoptimized + debuginfo] target(s) in 0.67s
     Running `target/debug/rust-getting-started`
Hello, world!
```

سه خط اول را Cargo چاپ می‌کند، نه برنامه‌ی ما. `Compiling` یعنی کامپایل شروع شد. `Finished` می‌گوید کار تمام شد و از کدام «پروفایل» (profile) استفاده شد؛ پروفایل را در بخش بعد توضیح می‌دهم. `Running` هم می‌گوید کدام فایل اجرایی را راه انداخته است. خط آخر، `Hello, world!`، خروجی خود برنامه است.

## Debug و release

دیدید که Cargo نوشت `dev` profile. Cargo دو شکل اصلی برای build دارد. `cargo build` یک نسخه‌ی **debug** می‌سازد: کامپایلش سریع است، چون کد را بهینه نمی‌کند، و اطلاعات کمکی برای اشکال‌یابی (debugger) در آن هست. خروجی در `target/debug/` می‌رود. `cargo build --release` بهینه‌سازی را روشن می‌کند. کامپایلش کندتر است ولی برنامه‌ی نهایی سریع‌تر اجرا می‌شود، و خروجی در `target/release/` می‌رود:

```bash
$ cargo build --release
    Finished `release` profile [optimized] target(s) in 0.15s
$ ls target
CACHEDIR.TAG  debug  release
$ ls -l target/debug/rust-getting-started target/release/rust-getting-started
-rwxr-xr-x@ 1 <user>  staff  444520 ... target/debug/rust-getting-started
-rwxr-xr-x@ 1 <user>  staff  406192 ... target/release/rust-getting-started
```

برای هر دو شکل یک پوشه‌ی جدا در `target/` ساخته شد. عدد ستون پنجم اندازه‌ی فایل به بایت است. برای یک hello world این دو عدد نزدیک به هم‌اند؛ تفاوت اصلی release را وقتی می‌بینید که برنامه کار سنگین بکند. (من اسم کاربری را با `<user>` عوض کرده‌ام. اندازه‌ها هم به نسخه‌ی کامپایلر و دستگاه بستگی دارند.) قاعده‌ی ساده: هنگام نوشتن کد از debug استفاده کنید و برای هر چیزی که اندازه‌گیری یا منتشر می‌کنید از `--release`.

## Check، format و lint

سه دستور کوچک دیگر هر روز به کارتان می‌آید:

- `cargo check` فقط بررسی می‌کند کد درست است یا نه (نوع‌ها و قاعده‌های زبان) و فایل اجرایی نمی‌سازد. برای همین از build کامل خیلی سریع‌تر است. من حین نوشتن کد زیاد اجرایش می‌کنم.
- `cargo fmt` کد را با ابزار `rustfmt` مرتب می‌کند، مثل `gofmt` در Go. `cargo fmt --check` چیزی را عوض نمی‌کند و فقط می‌گوید فایلی مرتب نیست.
- `cargo clippy` یک **linter** است: برنامه را می‌خواند و جاهایی را که درست کار می‌کنند ولی می‌شود بهتر نوشت یا احتمالاً اشتباه‌اند نشان می‌دهد. برنامه‌ی بخش بعد را با آن بررسی کردم و هیچ هشداری نداد.

## برنامه‌ای کمی بزرگ‌تر، با dependency

تا اینجا کدی ننوشته‌ایم. یک برنامه‌ی کوچک بنویسیم که از یک کتاب‌خانه‌ی بیرونی استفاده کند. در دنیای Rust به هر بسته‌ی کد، **crate** می‌گویند و crateهای عمومی در سایت crates.io منتشر می‌شوند. ما برای ساختن عدد تصادفی به crate با اسم `rand` نیاز داریم. اضافه‌کردنش یک دستور است (بار اول اینترنت لازم دارد):

```bash
$ cargo add rand
      Adding rand v0.10.3 to dependencies
```

Cargo خودش `Cargo.toml` را ویرایش کرد و زیر `[dependencies]` خطی مثل `rand = "0.10.3"` گذاشت. نسخه‌ی دقیقی که واقعاً استفاده شد هم در فایل `Cargo.lock` ثبت می‌شود. این فایل را Cargo خودش می‌سازد و لازم نیست دستی عوضش کنید.

حالا برنامه. کاری که می‌کند ساده است: یک آرگومان اختیاری از خط فرمان می‌گیرد و یک سلام همراه با یک عدد تصادفی بین ۱ تا ۱۰۰ چاپ می‌کند.

```rust
use std::env;

use rand::RngExt;

fn main() {
    // First CLI argument, or "world" when none is given.
    let name = env::args().nth(1).unwrap_or_else(|| "world".to_string());
    let lucky: u32 = rand::rng().random_range(1..=100);
    println!("Hello, {name}! Your lucky number is {lucky}.");
}
```

خط به خط:

- `env::args()` آرگومان‌های خط فرمان را می‌دهد. آرگومان شماره‌ی ۰ اسم خود برنامه است، پس `.nth(1)` اولین آرگومانی را برمی‌دارد که کاربر نوشته.
- ممکن است کاربر هیچ آرگومانی ندهد. برای همین `nth(1)` مقدار را داخل یک `Option` برمی‌گرداند، یعنی «یا چیزی هست یا نیست». `unwrap_or_else` می‌گوید اگر چیزی نبود، به‌جایش `"world"` را بگذار. `Option` را در مقاله‌های بعد درست توضیح می‌دهم؛ فعلاً همین معنی کافی است.
- `random_range(1..=100)` یک عدد از ۱ تا ۱۰۰ می‌دهد، که خود ۱۰۰ هم می‌تواند باشد.
- `println!` متن را چاپ می‌کند و هر چیزی که داخل `{}` باشد را با مقدار آن متغیر عوض می‌کند.

دو بار اجرایش می‌کنیم، یک بار بدون آرگومان و یک بار با اسم:

```bash
$ cargo run -q
Hello, world! Your lucky number is 82.
$ cargo run -q -- Roham
Hello, Roham! Your lucky number is 86.
```

گزینه‌ی `-q` (quiet) خط‌های `Compiling` و `Running` را حذف می‌کند تا فقط خروجی خود برنامه بماند. علامت `--` آرگومان‌های خود Cargo را از آرگومان‌های برنامه‌ی شما جدا می‌کند؛ هرچه بعد از آن بیاید به برنامه می‌رسد. بار اول چون آرگومانی نداشتیم، اسم پیش‌فرض `world` چاپ شد و بار دوم `Roham`. عدد تصادفی هم در هر اجرا فرق می‌کند، پس عددهای شما چیز دیگری خواهند بود.

## مقایسه‌ی ابزارهای Go و Rust

برای اینکه کارهای هر روزه را کنار هم ببینید:

| کار | Go | Rust |
| --- | --- | --- |
| پروژه‌ی جدید | `go mod init` | `cargo new` |
| Build و اجرا | `go run .` | `cargo run` |
| Build | `go build` | `cargo build` (با `--release` برای بهینه) |
| افزودن dependency | `go get` | `cargo add` |
| فرمت کد | `gofmt` / `go fmt` | `cargo fmt` |
| فایل dependency | `go.mod` | `Cargo.toml` (به‌همراه `Cargo.lock`) |

## دردسرهای رایج ابزارها

- **پوشه‌ی `target/` بزرگ می‌شود.** Cargo همه‌ی خروجی build را آنجا می‌ریزد. آن را در git نگذارید؛ `cargo new` خودش یک `.gitignore` می‌سازد که `target` را کنار می‌گذارد.
- **اولین build بعد از اضافه‌کردن dependency کند است.** Cargo crate را دانلود و کامپایل می‌کند. buildهای بعدی از نتیجه‌ی قبلی استفاده می‌کنند و سریع‌تر می‌شوند.
- **نسخه‌ی crateها عوض می‌شود و آموزش‌های قدیمی گمراه می‌کنند.** در نسخه‌ی 0.10 کتاب‌خانه‌ی `rand` برای `random_range` باید `use rand::RngExt` بنویسید. اگر در آموزشی قدیمی‌تر کد دیگری دیدید، اول نسخه را چک کنید.
- **برای هر کاری ابزار درست را بزنید.** هنگام ویرایش `cargo check` سریع‌ترین بازخورد را می‌دهد و هنگام سنجش سرعت باید `--release` را بزنید، چون سرعت build debug معنی‌دار نیست.
- **Clippy و rustfmt «component» هستند.** اگر روی دستگاه شما `cargo clippy` پیدا نشد، با `rustup component add clippy` نصبش کنید.

## تمرین

۱. برنامه را طوری تغییر دهید که دو آرگومان بگیرد، یک نام و یک حداکثر عدد، و عدد شانسی را از `1..=max` انتخاب کند. (راهنما: آرگومان‌ها رشته‌اند، پس باید دومی را parse کنید.)
۲. `cargo build --release` را بزنید و با `ls -l` فایل اجرایی را با نسخه‌ی debug مقایسه کنید.

## قدم بعدی

«نوع‌ها، متغیرها و کنترل جریان در Rust». حالا که برنامه‌ای می‌سازیم و اجرا می‌کنیم، وقت آن است که خود زبان را یاد بگیریم: واژگان پایه‌ی آن، جایی که immutable بودن، shadowing، `if` و `match` از همان ابتدا با Go فرق دارند.
