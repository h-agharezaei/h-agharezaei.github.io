از همان اولین برنامه‌ی Rust با ماکرو کار کرده‌اید، شاید بی‌آنکه متوجه باشید. `println!("{} و {}", a, b)` را در نظر بگیرید: هر تعداد آرگومان می‌گیرد، از هر نوعی، و رشته‌ی قالب را موقع کامپایل چک می‌کند. یک تابع معمولی در Rust هیچ‌کدام از این کارها را نمی‌کند، چون تعداد و نوع پارامترهایش ثابت است. علامت `!` در آخر اسم همان نشانه‌ی «این تابع نیست، ماکرو است». `vec![1, 2, 3]` هم ماکرو است و `#[derive(Debug)]` هم.

**ماکرو** یعنی کدی که کد می‌نویسد، و این کار را موقع کامپایل انجام می‌دهد، قبل از اینکه برنامه اجرا شود. در این مقاله دو نوع آن را از صفر می‌نویسیم: ماکروی ساده‌تر `macro_rules!` (به آن ماکروی {{< term "macro-rules" "declarative" >}} هم می‌گویند) و بعد یک ماکروی `derive`، از همان نوعی که `#[derive(Serialize)]` در [Serde و JSON در Rust](/fa/posts/rust-serde-json/) بود. این مقاله بعد از [Trait Object و dyn در Rust](/fa/posts/rust-trait-objects-dyn/) می‌آید: آن‌جا دیدیم چطور یک trait چند نوع را زیر یک نام جمع می‌کند و این‌جا ابزار دیگری برای جلوگیری از تکرار کد می‌بینیم.

> همه‌ی کدها را با Rust 1.90 (`rustc 1.90.0`)، `syn` نسخه‌ی 2.0.119، `quote` نسخه‌ی 1.0.47 و `proc-macro2` نسخه‌ی 1.0.107 (طبق `Cargo.lock` همان demo) دوباره اجرا کرده‌ام. خروجی‌ها از اجرای واقعی یک workspace محلی کپی شده‌اند. دو مثال کوچک (`add!` و `square!` با آرگومانی که اثر جانبی دارد) را فقط برای نمایش در برنامه‌های جدا نوشتم و اجرا کردم. در پیام‌های خطا مسیر پوشه‌ی موقت را با `<tmp>` عوض کرده‌ام و خط‌های «For more information…» را حذف کرده‌ام.

## ماکرو چه چیزی می‌گیرد و چه چیزی برمی‌گرداند؟

تابع مقدار می‌گیرد: عدد ۵، رشته‌ی `"سلام"`. ماکرو **token** می‌گیرد. token کوچک‌ترین تکه‌ی معنادار متن برنامه است: یک نام (`x`)، یک عدد (`5`)، یک علامت (`+`) یا یک جفت پرانتز. کامپایلر قبل از هر کاری برنامه را به token‌ها می‌شکند، و ماکرو در همین مرحله به آن‌ها دست می‌زند و توکن‌های دیگری تحویل می‌دهد. کامپایلر به‌جای فراخوانی ماکرو همان توکن‌های جدید را می‌گذارد و کامپایلشان می‌کند. به این جایگزینی **expansion** (باز شدن ماکرو) می‌گویند.

کوچک‌ترین مثال:

```rust
macro_rules! add {
    ($a:expr, $b:expr) => {
        $a + $b
    };
}

fn main() {
    println!("{}", add!(2, 3));
    println!("{}", add!(10 * 2, 5));
}
```

```text
5
25
```

ساختار `macro_rules!` یک یا چند «قاعده» است و هر قاعده دو نیمه دارد که با `=>` جدا شده‌اند:

- **الگو** (سمت چپ): شکلی از توکن‌ها که ماکرو باید ببیند. `$a:expr` یعنی «یک expression بگیر و اسمش را `$a` بگذار». بخش بعد از `:` را **fragment specifier** می‌گویند و به کامپایلر می‌گوید چه جور تکه‌ای را بپذیرد. چند نمونه‌ی رایج: `expr` (یک عبارت)، `ident` (یک نام)، `ty` (یک نوع) و `tt` (یک «درخت توکن»: یک توکن یا یک گروه توکن داخل پرانتز، منعطف‌ترین حالت).
- **قالب** (سمت راست): کدی که جای فراخوانی نوشته می‌شود، با `$a` و `$b` که با چیزهایی که گرفته‌ایم پر می‌شوند.

پس `add!(2, 3)` به `2 + 3` باز می‌شود و `add!(10 * 2, 5)` به `10 * 2 + 5`. خروجی ۲۵ همین را نشان می‌دهد. هر دو خط خروجی را خودم با اجرای همین برنامه‌ی کوچک دیدم.

## یک ماکروی کمی جدی‌تر: square! و دو تعجب

حالا `square!`:

```rust
macro_rules! square {
    ($x:expr) => { $x * $x };
}
```

`square!(3 + 1)` را اگر در C با `#define` می‌نوشتید، متن را عیناً جایگزین می‌کرد و می‌شد `3 + 1 * 3 + 1` که برابر ۷ است. این‌جا برنامه‌ی demo چاپ می‌کند:

```text
square!(3 + 1) = 16
```

دلیلش این است که یک fragment از نوع `expr` همچنان یک گره‌ی کامل از عبارت می‌ماند: `3 + 1` مثل یک مقدار واحد با پرانتز نامرئی جایگزین می‌شود. پس دام جایگزینی متنی در C اینجا وجود ندارد. `cargo expand` که ماکرو را باز و نمایش می‌دهد، تا جایی که می‌دانم، به یک compiler شبانه (nightly) نیاز دارد و من نصبش نکرده‌ام. به‌جای آن باز شدن را با یک تست ثابت می‌کنم:

```rust
assert_eq!(square!(3 + 1), (3 + 1) * (3 + 1));
```

```text
test tests::square_expansion_is_equivalent ... ok
```

تست می‌گوید `square!(3 + 1)` همان‌قدر است که خودمان `(3 + 1) * (3 + 1)` را بنویسیم، و هر دو ۱۶ هستند.

ولی یک تعجب دیگر هست. قالب `$x * $x` عبارت را **دو بار** می‌نویسد، پس اگر آن عبارت کاری بکند (چیزی چاپ کند، شمارنده‌ای را زیاد کند)، دو بار انجام می‌شود:

```rust
fn next(counter: &mut i32) -> i32 {
    *counter += 1;
    println!("next() called, counter = {counter}");
    *counter
}

let mut c = 0;
let r = square!(next(&mut c));
println!("result = {r}");
```

```text
next() called, counter = 1
next() called, counter = 2
result = 2
```

`next` دو بار صدا زده شد: یک بار برای `$x` اول (مقدار ۱) و یک بار برای `$x` دوم (مقدار ۲)، و نتیجه ۱ × ۲ = ۲ شد، نه ۱ × ۱. اگر این اتفاق را نمی‌خواهید، مقدار را اول در یک متغیر بگذارید. ماکروی بعدی همین کار را می‌کند.

## تکرار و بازگشت: max!

می‌خواهیم `max!(3, 9, 4)` را با هر تعداد آرگومان بنویسیم. ایده: بزرگ‌تر بین اولی و «بزرگ‌ترین باقی‌مانده». قاعده‌ی اول حالت یک عنصری را می‌گوید و قاعده‌ی دوم ماکرو را با باقی‌مانده دوباره صدا می‌زند:

```rust
macro_rules! max {
    ($x:expr) => ($x);
    ($x:expr, $($rest:expr),+) => {{
        let a = $x;
        let b = $crate::max!($($rest),+);
        if a > b { a } else { b }
    }};
}
```

عبارت `$(...),+` یک **تکرار** است: یعنی «یک یا چند مورد از این الگو، با کاما از هم جدا». `$($rest:expr),+` همه‌ی عبارت‌های باقی‌مانده را می‌گیرد، و `$($rest),+` در قالب همان‌ها را دوباره پشت هم با کاما می‌نویسد. `$crate::max!` یعنی «همین ماکرو از همین crate»؛ این شکل را برای ماکروهایی که export می‌شوند بنویسید تا بیرون از crate هم کار کنند. دو لایه‌ی `{{ }}` یعنی قالب یک بلوک است و می‌تواند `let` داشته باشد. چون هر عبارت اول در `a` می‌نشیند، اینجا (برخلاف `square!`) هر عبارت فقط یک بار محاسبه می‌شود.

```text
max!(3, 9, 4) = 9
max!(2.5, 1.5) = 2.5
```

برای هر نوعی که با `>` مقایسه شود کار می‌کند، چون ماکرو فقط کد می‌نویسد و کامپایلر بعداً نوع‌ها را چک می‌کند.

## ماکرو برای ساختن نوشته‌های تکراری

یک literal برای `HashMap` که Rust ندارد. این بار از `$(...),*` استفاده می‌کنیم، یعنی «صفر یا بیشتر»، و `$(,)?` اجازه می‌دهد آخر فهرست یک کامای اضافه بنویسید:

```rust
macro_rules! hashmap {
    ($($k:expr => $v:expr),* $(,)?) => {{
        let mut m = ::std::collections::HashMap::new();
        $( m.insert($k, $v); )*
        m
    }};
}
```

الگو می‌گوید «چند تا جفت `کلید => مقدار`». در قالب، بخش `$( m.insert($k, $v); )*` برای هر جفت یک خط `insert` می‌نویسد. `hashmap!{ "a" => 1, "b" => 2, }` خروجی `[("a", 1), ("b", 2)]` داد (قبل از چاپ مرتبش کردم چون ترتیب `HashMap` ثابت نیست). مسیر کامل `::std::collections::HashMap` را نوشته‌ام تا ماکرو در هر جا کار کند، حتی جایی که `HashMap` import نشده.

ماکرو می‌تواند تعریف کامل هم تولید کند، یعنی struct و enum و `impl`. این یکی یک نام و فهرستی از variantها می‌گیرد و هم enum را می‌سازد هم متدی که اسم هر variant را برمی‌گرداند:

```rust
macro_rules! make_enum {
    ($name:ident { $($variant:ident),+ $(,)? }) => {
        #[derive(Debug, Clone, Copy, PartialEq)]
        pub enum $name { $($variant),+ }
        impl $name {
            pub const ALL: &'static [$name] = &[$($name::$variant),+];
            pub fn name(&self) -> &'static str {
                match self { $($name::$variant => stringify!($variant)),+ }
            }
        }
    };
}
make_enum!(Color { Red, Green, Blue });
```

`stringify!($variant)` اسم variant را به رشته تبدیل می‌کند. پیمایش `Color::ALL` و چاپ `c.name()` برای هر عنصر سه خط `Red -> Red`، `Green -> Green` و `Blue -> Blue` داد (اولی نتیجه‌ی `{:?}` و دومی `name()` است، که اینجا یکی‌اند). یک `make_struct!(Point { x: i32, y: i32 })` هم با fragmentهای `ty` نوشتم که `Point::field_names()` را به شکل `["x", "y"]` چاپ کرد، و شمارنده‌ی مبتنی بر `tt` یعنی `count_tts!(a b c d)` عدد 4 را برگرداند.

## Hygiene: متغیرهای ماکرو با متغیرهای شما قاطی نمی‌شوند

در `max!` یک متغیر موقت به اسم `a` ساختیم. اگر شما هم در برنامه‌تان متغیری به اسم `a` داشته باشید و آن را به `max!` بدهید چه می‌شود؟ در ماکروهای C چنین برخوردی دردسرساز است. در Rust نه: به این ویژگی **hygiene** می‌گویند، یعنی نام‌هایی که داخل ماکرو ساخته می‌شوند و نام‌هایی که از بیرون می‌آیند، حتی اگر شبیه هم باشند، دو متغیر جدا هستند. در demo:

```rust
let a = 100;
let r = max!(a, 7);  // a = 100, max!(a, 7) = 100
let x = 10;
double_with_temp!(x) // macro has `let x = 2; $e * x` -> 20
```

```text
a = 100, max!(a, 7) = 100
double_with_temp!(x) = 20
```

در `double_with_temp!` قالب `let x = 2; $e * x` است. اگر `x` ماکرو و `x` من یکی بودند، `$e * x` می‌شد ۲ × ۲ = ۴. نتیجه ۲۰ است: `$e` همان `x` خودم (۱۰) است و ضرب در `x` داخلی ماکرو (۲) می‌شود ۲۰.

## وقتی ماکرو را اشتباه صدا می‌زنید

ماکرو چون الگو دارد، فراخوانی ناجور هم پیام دارد. `square!(3, 4)` به هیچ قاعده‌ای نمی‌خورد:

```text
error: no rules expected `,`
 --> demo/src/bin/bad_square.rs:3:29
  |
3 |     println!("{}", square!(3, 4));
  |                             ^ no rules expected this token in macro call
  |
note: while trying to match meta-variable `$x:expr`
 --> <tmp>/demo/src/lib.rs:3:6
  |
3 |     ($x:expr) => {
  |      ^^^^^^^
```

خط‌به‌خط: خطا روی کاما (ستون ۲۹) است، چون قاعده‌ی ما فقط یک `$x:expr` می‌پذیرد و بعد از آن توکن دیگری انتظار ندارد. بخش `note` می‌گوید کامپایلر داشت کدام قسمت از الگو را تطبیق می‌داد و با نشان دادن تعریف ماکرو (`lib.rs:3:6`) به شما می‌فهماند الگوی چه بوده. پس این پیام‌ها هم به محل فراخوانی اشاره می‌کنند هم به تعریف ماکرو.

## ماکروی procedural: ماکرو به‌عنوان یک تابع Rust

`macro_rules!` الگو و قالب است. گاهی این کافی نیست: مثلاً می‌خواهید روی یک struct `#[derive(Describe)]` بنویسید و ماکرو **فیلدهای struct** را بخواند و بر اساسشان کد بسازد. برای این کار از نوع دیگری استفاده می‌کنیم: {{< term "procedural-macro" "ماکروی procedural" >}}. این یک تابع معمولی Rust است که کامپایلر موقع کامپایل اجرایش می‌کند؛ توکن‌ها را می‌گیرد و توکن‌ها را برمی‌گرداند. هر کاری از Rust بلدید می‌توانید در آن بکنید.

یک محدودیت: ماکروی procedural باید در یک crate جدا با `proc-macro = true` در `Cargo.toml` باشد. پس demo یک workspace با دو crate دارد: `describe_derive` (خود ماکرو) و `demo` (کاربر آن). سه وابستگی کمک می‌کنند: `syn = "2"` توکن‌ها را به درخت نحوی قابل خواندن تبدیل می‌کند (مثلاً «این یک struct است با این فیلدها»)، `quote = "1"` از روی یک قالب شبیه کد Rust توکن می‌سازد، و `proc-macro2` نوع توکن مشترک بین آن‌ها است.

```rust
#[proc_macro_derive(Describe)]
pub fn derive_describe(input: TokenStream) -> TokenStream {
    let ast = parse_macro_input!(input as DeriveInput);
    let name = &ast.ident;
    let fields = match &ast.data {
        Data::Struct(s) => match &s.fields {
            Fields::Named(f) => &f.named,
            _ => return syn::Error::new_spanned(name,
                "Describe needs a struct with named fields").to_compile_error().into(),
        },
        _ => return syn::Error::new_spanned(name,
            "Describe can only be derived for structs").to_compile_error().into(),
    };
    let lines: Vec<String> = fields.iter().map(|f| {
        let ty = &f.ty;
        format!("{}: {}", f.ident.as_ref().unwrap(),
                quote!(#ty).to_string().replace(" ", ""))
    }).collect();
    let title = name.to_string();
    quote! {
        impl #name {
            pub fn describe() -> String {
                let mut out = String::from(#title);
                #( out.push_str("\n  "); out.push_str(#lines); )*
                out
            }
        }
    }.into()
}
```

قدم‌به‌قدم:

1. `#[proc_macro_derive(Describe)]` به کامپایلر می‌گوید این تابع پاسخ `#[derive(Describe)]` است. `input` توکن‌های خود struct است.
2. `parse_macro_input!` با `syn` آن توکن‌ها را به `DeriveInput` تبدیل می‌کند: نام نوع در `ast.ident` و محتوایش در `ast.data`.
3. `match` فقط structهای با فیلد نام‌دار را قبول می‌کند. برای هر چیز دیگر یک `syn::Error` برمی‌گردانیم که به یک `compile_error!` تبدیل می‌شود، یعنی خطای عادی کامپایلر، نه panic.
4. برای هر فیلد، یک رشته‌ی `نام: نوع` می‌سازیم.
5. `quote!` قالب کدی را که باید نوشته شود می‌سازد: یک `impl` با متد `describe`. `#name` و `#title` مقدارهای بالا را داخل قالب می‌گذارند و `#( ... )*` برای هر عضو `lines` یک بار تکرار می‌شود، مثل `$(...)*` در `macro_rules!`.

استفاده: `#[derive(Describe)] struct User { name: String, age: u32, tags: Vec<String>, email: Option<String> }` و بعد `println!("{}", User::describe())`:

```text
User
  name: String
  age: u32
  tags: Vec<String>
  email: Option<String>
```

ماکرو هیچ‌وقت `User` را اجرا نکرد؛ فقط در زمان کامپایل از روی تعریفش یک `impl` نوشت، و ما آن را مثل هر تابع دیگری صدا زدیم. روی یک `enum` ماکرو یک خطای وابسته به span (جای مشخصی از کد، این‌جا نام `Shape`) برمی‌گرداند، پس پیام در جای درست نشان داده می‌شود:

```text
error: Describe can only be derived for structs
 --> demo/src/bin/bad_derive.rs:4:6
  |
4 | enum Shape {
  |      ^^^^^
```

`serde` را هم از همین دید ببینید: تا جایی که می‌دانم، derive آن هم با `syn` فیلدهای struct شما را می‌خواند و با `quote` کد `impl Serialize` را می‌نویسد و attributeهایی مثل `#[serde(rename)]` را هم اعمال می‌کند. همین شکل کلی `Describe` ما است، فقط خیلی کامل‌تر.

دو نوع دیگر از ماکروی procedural هم هست که ننوشتم: **attribute-like** که شکلش `#[route(GET, "/")]` است و آیتمی را که رویش گذاشته‌اید جایگزین می‌کند، و **function-like** که مثل `macro_rules!` صدا زده می‌شود (`sql!(...)`) اما با کد Rust نوشته شده است. اصل ماجرا در هر سه یکی است: توکن می‌آید و توکن بیرون می‌رود.

## هزینه‌ها و عادت‌های خوب

- **تابع یا generics را ترجیح بدهید.** فقط برای آرگومان‌های متغیر، سینتکس تازه یا تولید تعریف‌های تکراری سراغ ماکرو بروید. اگر یک تابع کار را می‌کند، ماکرو لازم نیست.
- **ماکرو هزینه دارد.** ساخت crate ماکرو و `syn` زمان کامپایل را بیشتر می‌کند، خواندن ماکرو برای دیگران سخت‌تر است و پیام خطایش معمولاً مبهم‌تر از خطای یک تابع.
- **با ورودی کوچک و تست کوچک اشکال‌زدایی کنید.** باز کردن دستی مثل `square!` و یک `assert_eq!` عادت خوبی است.
- **داخل ماکروهای export شده** همیشه `$crate::` و مسیر کامل مثل `::std::collections::HashMap` را بنویسید، چون نمی‌دانید فراخواننده چه چیزهایی import کرده.
- **به‌جای panic، `syn::Error` با span مناسب برگردانید** تا کاربر ماکرو خطا را روی کد خودش ببیند.
- **حواستان به دوبار ارزیابی باشد.** اگر قالب یک `$x` را بیش از یک بار می‌نویسد، آن را در `let` بگیرید، مثل کاری که `max!` کرد.

## تمرین

1. ماکروی `min!` را شبیه `max!` بنویسید و `min!(5, 2, 8)` را تست کنید.
2. `Describe` را طوری گسترش دهید که `field_count() -> usize` هم تولید کند.
3. `square!` را طوری عوض کنید که آرگومان فقط یک بار محاسبه شود و دوباره مثال `next` را اجرا کنید.
