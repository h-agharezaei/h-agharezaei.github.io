یک عدد `u8` را در نظر بگیرید، یعنی عدد صحیحی که فقط می‌تواند بین ۰ تا ۲۵۵ باشد. مقدارش ۲۵۵ است و ۱ به آن اضافه می‌کنید. جواب چیست؟ ۲۵۶ نمی‌شود، چون در این نوع جا ندارد. در Rust جواب به نحوه‌ی build بستگی دارد: در حالت debug برنامه با panic متوقف می‌شود و در حالت `--release` بی‌صدا به ۰ برمی‌گردد. در Go چنین {{< term "integer-overflow" "سرریزی (overflow)" >}} همیشه بی‌صدا دور می‌زند.

واژگان پایه‌ی Rust، یعنی تعریف متغیر، نوع‌ها، شرط و حلقه، پر از همین نمونه‌هاست. اگر از Go آمده باشید بیشترش آشناست، ولی چند پیش‌فرض دقیقاً برعکس چیزی است که انتظار دارید. این مقاله همان‌ها را یکی‌یکی نشان می‌دهد، و هرجا کامپایلر اعتراض می‌کند، پیامش را می‌خوانیم تا یاد بگیریم Rust چه می‌گوید. اگر هنوز Rust و Cargo را راه نینداخته‌اید، از [شروع کار با Rust](/fa/posts/rust-getting-started/) شروع کنید.

> همه‌ی کدهای زیر را با Rust 1.90 (`rustc 1.90.0`) کامپایل و اجرا کرده‌ام و خروجی‌ها واقعی‌اند. پیام‌های خطا را فقط کمی کوتاه کرده‌ام و جاهایی که کوتاه شده‌اند را در متن گفته‌ام.

## متغیرها به‌طور پیش‌فرض تغییرناپذیرند

در Rust دستور `let` متغیری می‌سازد که بعد از مقداردهی اول دیگر عوض نمی‌شود. به چنین متغیری **immutable** می‌گویند. ببینید اگر بخواهیم مقدارش را عوض کنیم چه می‌شود:

```rust
fn main() {
    let x = 5;
    x = 6;
    println!("{x}");
}
```

کامپایل این برنامه شکست می‌خورد. این پیام کامپایلر است:

```text
warning: value assigned to `x` is never read
 --> src/bin/immut.rs:2:9
  |
2 |     let x = 5;
  |         ^
  |
  = help: maybe it is overwritten before being read?
  = note: `#[warn(unused_assignments)]` on by default

error[E0384]: cannot assign twice to immutable variable `x`
 --> src/bin/immut.rs:3:5
  |
2 |     let x = 5;
  |         - first assignment to `x`
3 |     x = 6;
  |     ^^^^^ cannot assign twice to immutable variable
  |
help: consider making this binding mutable
  |
2 |     let mut x = 5;
  |         +++

For more information about this error, try `rustc --explain E0384`.
error: could not compile `rust-types-control-flow` (bin "immut") due to 1 previous error; 1 warning emitted
```

این اولین پیام خطای کامپایلر در این سری است، پس ساختارش را یک بار با هم می‌خوانیم. بقیه‌ی پیام‌ها هم همین شکل را دارند:

- بالا یک `warning` هست. هشدار مانع کامپایل نمی‌شود و فقط می‌گوید مقدار ۵ هیچ‌وقت خوانده نشد، چون قبل از خواندن عوض شده. این هشدار فرع ماجراست.
- `error[E0384]` خطای اصلی است. داخل کروشه، کد خطاست و عنوان بعدش می‌گوید مشکل چیست: «نمی‌شود دو بار به متغیر immutable مقدار داد».
- خط `-->` جای مشکل را می‌دهد: فایل، شماره‌ی خط و شماره‌ی ستون.
- زیر آن، کامپایلر خطوط کد را با شماره نشان می‌دهد و با علامت‌های `-` و `^` مشخص می‌کند کدام قسمت مهم است. اینجا `-` اولین مقداردهی را نشان می‌دهد و `^^^^^` انتساب دومی را که مشکل‌ساز است.
- `help` راه‌حل را پیشنهاد می‌کند: `let mut x`. علامت‌های `+++` می‌گویند چه چیزی باید اضافه شود.
- خط آخر می‌گوید با `rustc --explain E0384` توضیح مفصل‌تری درباره‌ی این خطا می‌گیرید.

پس اگر واقعاً می‌خواهید متغیر عوض شود، باید با `mut` صریحاً بگویید. در Go هر متغیری قابل تغییر است. در Rust شما خودتان اجازه می‌دهید، و خواننده‌ی کد با یک نگاه می‌فهمد چه چیزهایی ممکن است عوض شوند.

## Shadowing با تغییر مقدار فرق دارد

شاید فکر کنید پس چطور می‌شود مقداری را یک بار حساب کرد و بعد به شکل دیگری از آن استفاده کرد. یک راه این است که با `let` دوباره متغیری هم‌نام تعریف کنید. به این کار {{< term "shadowing" "shadowing" >}} می‌گویند. متغیر قبلی عوض نمی‌شود؛ یک متغیر کاملاً جدید با همان اسم ساخته می‌شود که از آن لحظه به بعد اسم را «می‌پوشاند». برای همین متغیر جدید حتی می‌تواند نوع دیگری داشته باشد. در برنامه‌ی زیر هر دو کار را می‌بینید: shadowing و تغییر واقعی با `mut`:

```rust
fn main() {
    let spaces = "   ";
    let spaces = spaces.len(); // shadowing: new variable, new type
    println!("{spaces}");

    let mut count = 0;
    count += 1; // mutation: same variable, same type
    println!("{count}");

    let mut s = "abc";
    s = 5; // type change not allowed
}
```

خط دوم، `let spaces = spaces.len()`، متغیر جدیدی می‌سازد که عدد است، نه رشته. `count += 1` همان متغیر قبلی را عوض می‌کند. تفاوتشان این است که تغییر مقدار (mutation) نوع را ثابت نگه می‌دارد. آخرین دو خط همین را نشان می‌دهند: `s` یک رشته است و نمی‌شود عدد ۵ را در آن گذاشت:

```text
error[E0308]: mismatched types
  --> src/bin/shadow.rs:11:9
   |
10 |     let mut s = "abc";
   |                 ----- expected due to this value
11 |     s = 5; // type change not allowed
   |         ^ expected `&str`, found integer
```

`mismatched types` یعنی نوع‌ها نمی‌خوانند. کامپایلر نشان می‌دهد چرا انتظار یک `&str` (نوع رشته‌ی ثابت) داشته: به خاطر مقداری که در خط ۱۰ داده‌ایم. اما در خط ۱۱ یک عدد صحیح (`integer`) پیدا کرده. (این تنها خطای این برنامه است؛ دو خط اولش بدون مشکل‌اند.)

## نوع‌های اسکالر، tuple و array

نوع هر مقدار در Rust در زمان کامپایل معلوم است. ساده‌ترین نوع‌ها را اسکالر می‌نامند، یعنی هرکدام فقط یک مقدار تنها نگه می‌دارند:

- عدد صحیح علامت‌دار (می‌تواند منفی باشد): از `i8` تا `i128`، و `isize`.
- عدد صحیح بدون علامت (فقط ۰ و مثبت): از `u8` تا `u128`، و `usize`. عدد بعد از حرف، تعداد بیت‌هاست. `usize` هم به اندازه‌ی اشاره‌گر روی آن دستگاه است (روی دستگاه من ۸ بایت)، و برای اندیس و اندازه‌ی مجموعه‌ها استفاده می‌شود.
- عدد اعشاری: `f32` و `f64`.
- `bool`: درست یا نادرست.
- `char`: یک کاراکتر. یک Unicode scalar value است، پس ۴ بایت جا می‌گیرد و می‌تواند `'ز'` را هم نگه دارد.

علاوه بر اسکالرها، دو نوع مرکب ساده هم داریم. **Tuple** چند مقدار را، که می‌توانند نوع‌های متفاوت داشته باشند، کنار هم نگه می‌دارد و طولش ثابت است. **Array** چند مقدار هم‌نوع است، آن هم با طول ثابت. (برای فهرستی که بتواند بزرگ شود، بعداً سراغ `Vec` می‌رویم.) برنامه‌ی زیر همه‌ی این‌ها را یک‌جا نشان می‌دهد:

```rust
const MAX_POINTS: u32 = 100_000;

fn main() {
    let a = 42; // inferred i32
    let b: u64 = 10_000_000_000;
    let c = 2.5; // f64
    let d: f32 = 1.5;
    let ok = true;
    let ch = 'ز';
    let t: (i32, f64, char) = (1, 2.5, 'x');
    let (x, y, z) = t;
    let arr = [10, 20, 30];
    let zeros = [0u8; 4];
    println!("{a} {b} {c} {d} {ok} {ch}");
    println!("{} {} {} {}", t.0, x, y, z);
    println!("{} {} {:?} {:?}", arr[0], arr.len(), arr, zeros);
    println!("{MAX_POINTS}");
    println!("char size = {} bytes, i32 = {}, usize = {}", std::mem::size_of::<char>(), std::mem::size_of::<i32>(), std::mem::size_of::<usize>());
    let n: i32 = "42".parse().unwrap();
    println!("{}", n + a);
}
```

خروجی:

```text
42 10000000000 2.5 1.5 true ز
1 1 2.5 x
10 3 [10, 20, 30] [0, 0, 0, 0]
100000
char size = 4 bytes, i32 = 4, usize = 8
84
```

خط به خط:

1. چاپ `a` تا `ch`. برای `a` و `c` نوع ننوشته‌ایم و کامپایلر خودش حدس زده است (`i32` و `f64`).
2. `t.0` عضو اول tuple است. `let (x, y, z) = t` tuple را به سه متغیر جدا باز می‌کند (به آن destructuring می‌گویند)، برای همین `x` و `y` و `z` همان اعضای `t` هستند.
3. `arr[0]` عضو اول آرایه است و `arr.len()` طولش. `{:?}` شکل مناسب برای اشکال‌یابی (debug) چاپ می‌کند و برای آرایه لازم است. `[0u8; 4]` یعنی آرایه‌ای با چهار عضو که همه‌شان `0` از نوع `u8` هستند.
4. مقدار ثابت `MAX_POINTS`.
5. اندازه‌ها بر حسب بایت: `char` ۴ بایت، `i32` هم ۴ بایت، و `usize` روی این دستگاه ۸ بایت.
6. `"42".parse()` رشته را به عدد تبدیل می‌کند. `unwrap()` می‌گوید «اگر تبدیل موفق نبود، برنامه را متوقف کن»؛ در مقاله‌ی خطاها بهتر از آن را یاد می‌گیریم.

چند نکته درباره‌ی کد بالا:

- Rust نوع را حدس می‌زند. عدد صحیح به‌طور پیش‌فرض `i32` و عدد اعشاری `f64` است. فقط وقتی حدس ممکن نیست، مثل `parse()` که نمی‌داند به چه عددی تبدیل کند، نوع را صریح می‌نویسیم.
- `const` همیشه نوع صریح می‌خواهد، مقدارش باید در زمان کامپایل معلوم باشد و `mut` نمی‌شود. زیرخط در عدد (`100_000`) فقط برای خواناتر شدن است.
- بین نوع‌های عددی تبدیل خودکار وجود ندارد. باید خودتان تبدیل کنید، مثلاً با `as`. Go هم در این مورد همین‌طور است. ببینید اگر `i32` را با `i64` جمع کنیم چه می‌شود:

```rust
fn main() {
    let a: i32 = 5;
    let b: i64 = 10;
    println!("{}", a + b);
}
```

```text
error[E0308]: mismatched types
 --> src/bin/mismatch.rs:4:24
  |
4 |     println!("{}", a + b);
  |                        ^ expected `i32`, found `i64`

error[E0277]: cannot add `i64` to `i32`
 --> src/bin/mismatch.rs:4:22
  |
4 |     println!("{}", a + b);
  |                      ^ no implementation for `i32 + i64`
  |
  = help: the trait `Add<i64>` is not implemented for `i32`
  = help: the following other types implement trait `Add<Rhs>`:
            `&i32` implements `Add<i32>`
            `&i32` implements `Add`
            `i32` implements `Add<&i32>`
            `i32` implements `Add`

Some errors have detailed explanations: E0277, E0308.
For more information about an error, try `rustc --explain E0277`.
error: could not compile `rust-types-control-flow` (bin "mismatch") due to 2 previous errors
```

دو خطا برای یک اشتباه گزارش شده. خطای اول ساده است: سمت راست جمع باید `i32` می‌بود، ولی `i64` است. خطای دوم همان را از زاویه‌ی دیگری می‌گوید: برای جمع `i32 + i64` هیچ پیاده‌سازی‌ای وجود ندارد. در Rust جمع هم از طریق یک {{< term "trait" "trait" >}} به اسم `Add` کار می‌کند، و خط‌های `help` فهرست جمع‌هایی را می‌دهند که واقعاً تعریف شده‌اند و هیچ‌کدام `i32` با `i64` نیست. راه‌حل این است که یکی را تبدیل کنید، مثلاً `i64::from(a) + b`. دقت کنید که اینجا `trait` را فقط برای خواندن پیام لازم دارید؛ در مقاله‌های بعد درست توضیحش می‌دهم.

## سرریز عدد صحیح

برگردیم به سؤال اول مقاله. برنامه‌ی زیر یک عدد `u8` را از خط فرمان می‌گیرد، یک واحد به آن اضافه می‌کند و چاپش می‌کند. بعد چهار روش صریح برای جمع را کنار هم می‌گذارد:

```rust
fn main() {
    let n: u8 = std::env::args().nth(1).unwrap().parse().unwrap();
    let m = n + 1;
    println!("{m}");
    println!("{:?} {:?} {} {}", n.checked_add(1), n.wrapping_add(1), n.saturating_add(1), n.overflowing_add(1).1);
}
```

اول با ۲۵۰ اجرا می‌کنیم که جا دارد و بعد با ۲۵۵ در هر دو حالت build:

```text
$ cargo run -q --bin overflow 250
251
Some(251) 251 251 false

$ cargo run -q --bin overflow 255
thread 'main' panicked at src/bin/overflow.rs:3:13:
attempt to add with overflow
note: run with `RUST_BACKTRACE=1` environment variable to display a backtrace

$ cargo run -q --release --bin overflow 255
0
None 0 255 true
```

با ۲۵۰ همه‌چیز عادی است. با ۲۵۵ در build حالت debug، برنامه با **panic** متوقف می‌شود. panic روش Rust برای متوقف‌کردن برنامه در خطای غیرقابل‌جبران است: پیامی با محل مشکل (فایل و خط و ستون) چاپ می‌شود و برنامه تمام می‌شود. ولی در build حالت `--release` سرریز بی‌صدا دور می‌زند: ۲۵۵ + ۱ می‌شود ۰ و برنامه ادامه می‌دهد (طبق مستندات Rust این رفتار پیش‌فرض است و با تنظیمات پروژه عوض می‌شود).

چون این تفاوت راحت دردسر می‌سازد، بهتر است منظورتان را صریح بنویسید. خط آخر خروجی چهار انتخاب را نشان می‌دهد:

- `checked_add` یک `Option` برمی‌گرداند: `Some(251)` یعنی جمع جا شد و جواب این است، و `None` یعنی سرریز شد.
- `wrapping_add` عمداً دور می‌زند: ۲۵۵ + ۱ می‌شود ۰.
- `saturating_add` روی بیشترین مقدار می‌ایستد: ۲۵۵.
- `overflowing_add` جوابِ دورخورده را به‌همراه یک `bool` برمی‌گرداند که می‌گوید سرریز شد یا نه. ما فقط همان `bool` (`.1`) را چاپ کردیم.

یادآوری: در Go سرریز عدد صحیح همیشه بی‌صدا دور می‌زند.

## Statement و expression

یک تفاوت مهم دیگر با Go: در Rust تقریباً همه‌چیز یک expression است، یعنی چیزی که مقدار دارد. آخرین expression یک بلاک، **بدون سمی‌کالن**، مقدار کل آن بلاک است. برای همین تابعِ زیر `return` لازم ندارد:

```rust
fn square(x: i32) -> i32 {
    x * x
}
```

اگر به آخر یک expression سمی‌کالن بگذارید، به statement تبدیل می‌شود، که مقدارش `()` است (یعنی «هیچ»). ببینید در تابع `square` این اشتباه چه خطایی می‌دهد:

```rust
fn square(x: i32) -> i32 {
    x * x;
}
fn main() { println!("{}", square(2)); }
```

```text
error[E0308]: mismatched types
 --> src/bin/semi.rs:1:22
  |
1 | fn square(x: i32) -> i32 {
  |    ------            ^^^ expected `i32`, found `()`
  |    |
  |    implicitly returns `()` as its body has no tail or `return` expression
2 |     x * x;
  |          - help: remove this semicolon to return this value
```

تابع قول داده بود `i32` برگرداند (`^^^`) ولی چون بدنه با سمی‌کالن تمام شده، چیزی جز `()` برنمی‌گرداند. کامپایلر دقیقاً علت را هم می‌گوید: بدنه‌ی تابع «دم» (tail) ندارد، یعنی expression آخری بدون سمی‌کالن. و راه‌حل را روی همان سمی‌کالن نشان می‌دهد: آن را بردارید.

## کنترل جریان

چون `if` هم expression است، می‌تواند مقدار برگرداند و جای عملگر سه‌تایی (`? :`) را که در Go نیست و در بعضی زبان‌ها هست پر کند. دو قاعده دارد: شرط باید حتماً `bool` باشد (عدد صحیح قبول نمی‌شود)، و هر دو شاخه باید نوع یکسان داشته باشند. برنامه‌ی زیر هر دو قاعده را می‌شکند:

```rust
fn main() {
    let n = 1;
    let v = if n > 0 { 1 } else { "no" };
    if n { println!("x"); }
}
```

```text
error[E0308]: `if` and `else` have incompatible types
 --> src/bin/ifmis.rs:3:35
  |
3 |     let v = if n > 0 { 1 } else { "no" };
  |                        -          ^^^^ expected integer, found `&str`
  |                        |
  |                        expected because of this

error[E0308]: mismatched types
 --> src/bin/ifmis.rs:4:8
  |
4 |     if n { println!("x"); }
  |        ^ expected `bool`, found integer
```

خطای اول: شاخه‌ی `if` عدد صحیح برمی‌گرداند و شاخه‌ی `else` رشته. برای اینکه کل `if` یک نوع داشته باشد، هر دو باید یکی باشند. خطای دوم: `n` عدد است، نه `bool`. باید `if n != 0` نوشت. نسخه‌ی درست:

```rust
let kind = if n % 2 == 0 { "even" } else { "odd" };
```

**`loop`** تا وقتی `break` نزنید بی‌نهایت اجرا می‌شود، و `break` می‌تواند مقداری هم برگرداند. **`while`** همان حلقه‌ی شرطی معمولی است. **`for`** روی هر چیزی که بشود پیمایشش کرد کار می‌کند؛ `for` سه‌قسمتیِ سبک C (`for i := 0; i < n; i++`) در Rust وجود ندارد. بازه‌ها هم دو شکل دارند: `1..4` انتها را شامل نمی‌شود و `1..=4` می‌شود. **`match`** یک مقدار را با چند الگو مقایسه می‌کند و اولین الگوی منطبق را انتخاب می‌کند. اینجا فقط نمونه‌اش را می‌بینید؛ pattern matching مقاله‌ی جدا دارد. این برنامه همه‌ی این‌ها را یک‌جا نشان می‌دهد:

```rust
fn main() {
    let n = 7;
    let kind = if n % 2 == 0 { "even" } else { "odd" };
    println!("{n} is {kind}");

    let mut tries = 0;
    let found = loop {
        tries += 1;
        if tries * tries > 50 {
            break tries;
        }
    };
    println!("first n with n*n > 50: {found}");

    let mut k = 3;
    while k > 0 {
        println!("k = {k}");
        k -= 1;
    }

    for i in 1..4 { print!("{i} "); }
    for i in 1..=4 { print!("{i} "); }
    for i in (1..4).rev() { print!("{i} "); }
    println!();
    let names = ["a", "b"];
    for (i, name) in names.iter().enumerate() { println!("{i}: {name}"); }

    let code = 404;
    let msg = match code {
        200 => "ok",
        404 => "not found",
        500..=599 => "server error",
        _ => "other",
    };
    println!("{msg}");
    println!("{}", square(4));
}

fn square(x: i32) -> i32 {
    x * x
}
```

```text
7 is odd
first n with n*n > 50: 8
k = 3
k = 2
k = 1
1 2 3 1 2 3 4 3 2 1 
0: a
1: b
not found
16
```

- خط اول: ۷ فرد است. خط دوم: `loop` اولین `tries` را پیدا می‌کند که مربعش از ۵۰ بیشتر است. ۷ × ۷ = ۴۹ هنوز کم است و ۸ × ۸ = ۶۴ شد، پس `break tries` مقدار ۸ را به `found` می‌دهد.
- سه خط `k = ...` از `while`. شمارنده تا صفر پایین می‌آید.
- خط `1 2 3 1 2 3 4 3 2 1` سه حلقه‌ی `for` پشت سر هم روی یک خط است: `1..4` یعنی ۱ تا ۳، `1..=4` یعنی ۱ تا ۴، و `(1..4).rev()` یعنی ۳ تا ۱ برعکس.
- `enumerate()` به هر عضو شماره‌اش را هم اضافه می‌کند، پس `0: a` و `1: b` را می‌بینیم.
- `404` به الگوی دوم `match` می‌خورد: `not found`.
- `square(4)` همان تابع `square` بدون سمی‌کالن است و ۱۶ می‌دهد.

کامپایلر `match` را موظف می‌کند همه‌ی حالت‌های ممکن را پوشش دهید، و برای همین شاخه‌ی `_` ته آن هست: یعنی «هر چیز دیگر».

## کنار هم گذاشتن

یک برنامه‌ی کوچک آخر برای جمع‌بندی: جدول تبدیل دما از سلسیوس به فارنهایت (با یک توضیح برای هر ردیف) و بعد FizzBuzz تا ۱۵. در ستون‌بندی، `{c:>4}` یعنی «راست‌چین در عرض ۴» و `{f:>6.1}` یعنی «راست‌چین در عرض ۶ با یک رقم اعشار».

```rust
fn main() {
    println!("   C      F");
    for c in (-10..=40).step_by(10) {
        let f = c as f64 * 9.0 / 5.0 + 32.0;
        let note = match c {
            i32::MIN..=-1 => "freezing",
            0..=24 => "mild",
            _ => "hot",
        };
        println!("{c:>4} {f:>6.1}  {note}");
    }
    for i in 1..=15 {
        let s = if i % 15 == 0 { "FizzBuzz".to_string() }
            else if i % 3 == 0 { "Fizz".to_string() }
            else if i % 5 == 0 { "Buzz".to_string() }
            else { i.to_string() };
        print!("{s} ");
    }
    println!();
}
```

```text
   C      F
 -10   14.0  freezing
   0   32.0  mild
  10   50.0  mild
  20   68.0  mild
  30   86.0  hot
  40  104.0  hot
1 2 Fizz 4 Buzz Fizz 7 8 Fizz Buzz 11 Fizz 13 14 FizzBuzz 
```

`step_by(10)` حلقه را از ۱۰- تا ۴۰ ده‌تا ده‌تا جلو می‌برد. `c as f64` عدد صحیح را به اعشاری تبدیل می‌کند (همان تبدیل صریح که بالا گفتیم). `match` روی بازه‌ها کار می‌کند: زیر صفر `freezing`، ۰ تا ۲۴ `mild` و هرچه بیشتر `hot`. در FizzBuzz هم دیدید که `if` و `else if` جای یک expression نشسته‌اند و مقدار `s` را می‌سازند. (تمام شاخه‌ها `String` برمی‌گردانند، برای همین `.to_string()` لازم بود.)

## دام‌های رایج برای تازه‌کارها

- **سمی‌کالنِ آخر تابع.** خطای کلاسیک مبتدی‌هاست. دیدید که پیام کامپایلر دقیقاً به همان سمی‌کالن اشاره می‌کند، پس اگر `expected i32, found ()` دیدید اول آخر تابع را نگاه کنید.
- **debug و release در سرریز فرق دارند.** تستی که در debug panic می‌دهد ممکن است در release بی‌صدا جواب غلط بدهد. جایی که مهم است، از `checked_*` استفاده کنید تا رفتار در هر دو حالت یکی باشد.
- **اندیس array در زمان اجرا بررسی می‌شود.** اگر اندیس را در زمان اجرا بدهید (مثلاً از خط فرمان بخوانید و بشود ۵) و آرایه ۳ عضو داشته باشد، برنامه panic می‌دهد و مثل C حافظه‌ی بیرون آرایه را نمی‌خواند. پیام واقعی این است:

  ```text
  thread 'main' panicked at src/bin/idx.rs:4:20:
  index out of bounds: the len is 3 but the index is 5
  ```

- **Shadowing را زیاد نکنید.** برای تبدیل‌ها خوب است (`let x = x.trim();`)، ولی اگر یک اسم ده بار پوشانده شود، خواندن کد سخت می‌شود.
- **بازه‌ها:** `1..4` انتها را شامل نمی‌شود و `1..=4` می‌شود. یادتان باشد کدام را می‌خواهید.

## تمرین

۱. تابع `fn is_leap(year: u32) -> bool` را فقط با یک expression و بدون `return` بنویسید و سال‌های کبیسه‌ی بین ۱۹۹۰ تا ۲۰۳۰ را چاپ کنید.
۲. با `loop` و `break value` اولین توان ۲ بزرگ‌تر از ۱۰۰۰ را پیدا کنید.
۳. برنامه‌ی سرریز را طوری تغییر دهید که نتیجه‌ی `checked_add` را برای ۲۵۰ و ۲۵۵ چاپ کند و با `wrapping_add` مقایسه کنید.
